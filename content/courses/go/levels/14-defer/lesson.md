# defer: отложенное выполнение

Ваши функции становятся всё разветвлённее: ранние `return`, ветки ошибок, циклы. И в каждой ветке легко забыть финальное действие — «в самом конце обязательно сделай вот это». В Go для таких обещаний есть ключевое слово `defer`: отложенный вызов (*deferred call*). Вы говорите «выполни потом», и язык выполняет — при выходе из функции, каким бы путём этот выход ни случился.

## Что делает defer

Поставьте `defer` перед вызовом функции — и вызов не выполнится сразу, а встанет в очередь до выхода из текущей функции:

```go
package main

import "fmt"

func main() {
	defer fmt.Println("пока")
	fmt.Println("привет")
}
```

```
привет
пока
```

Строка с `defer` стоит первой по тексту, но напечаталась последней: Go запомнил вызов и произвёл его перед самым выходом из `main`.

> [!NOTE]
> Отложить можно только **вызов** функции — со скобками: `defer f()`. Просто `defer f` без скобок не скомпилируется: `expression in defer must be function call`.

## Любой путь выхода — один финал

Теперь главное. Сколько бы `return` ни было в функции, отложенный вызов сработает при **каждом** из них:

```go
func visit(hour int) {
	defer fmt.Println("— дверь закрыта —")

	if hour < 9 {
		fmt.Println("ещё не открылись")
		return
	}
	if hour >= 18 {
		fmt.Println("уже закрылись")
		return
	}
	fmt.Println("проходите!")
}
```

Вызов `visit(7)` уходит через первый `return`, но финал всё равно на месте:

```
ещё не открылись
— дверь закрыта —
```

В этом практическая ценность `defer`: финальное действие невозможно забыть в одной из веток. Функцию потом доработают, добавят третий и четвёртый `return` — гарантия останется.

Одна тонкость: `defer` регистрирует вызов только тогда, когда выполнение **дошло до этой строки**. Если функция вышла через `return` раньше, чем встретила `defer`, — откладывать было некому. Поэтому `defer` ставят как можно ближе к началу функции.

## Несколько defer: порядок LIFO

Отложенные вызовы складываются в стопку (*stack*): кто зарегистрировался последним, выполнится первым. Порядок называется LIFO (*last in, first out*) — как стопка тарелок: кладёте сверху, берёте тоже сверху.

```go
package main

import "fmt"

func main() {
	defer fmt.Println("один")
	defer fmt.Println("два")
	defer fmt.Println("три")
	fmt.Println("старт")
}
```

```
старт
три
два
один
```

| Порядок регистрации | Порядок выполнения |
|---|---|
| `defer ... ("один")` — первый | третьим |
| `defer ... ("два")` — второй | вторым |
| `defer ... ("три")` — третий | первым |

Зачем так? Освобождать ресурсы естественно в порядке, обратном получению: что открыли последним, закрываем первым — как матрёшку.

## Ловушка: аргументы фиксируются сразу

Классический вопрос с собеседований. Что напечатает эта программа?

```go
package main

import "fmt"

func main() {
	x := 1
	defer fmt.Println("отложенный:", x)
	x = 2
	fmt.Println("текущий:", x)
}
```

```
текущий: 2
отложенный: 1
```

Не 2, а 1! Аргументы отложенного вызова вычисляются **в момент `defer`**, а не при выполнении. Go как будто кладёт вызов в конверт: `fmt.Println("отложенный:", 1)` — с уже подставленным значением. Откладывается только сам вызов, не вычисление аргументов.

Это касается любых выражений в аргументах — они тоже считаются сразу:

```go
package main

import "fmt"

func main() {
	a, b := 2, 3
	defer fmt.Println("сумма:", a+b)
	a = 100
	fmt.Println("a теперь", a)
}
```

```
a теперь 100
сумма: 5
```

В конверт легло уже готовое число `5`: выражение `a+b` вычислилось на строке с `defer`, и позднейшее `a = 100` ничего не изменило.

## defer + замыкание: видит актуальное значение

А если финальному действию нужно **свежее** значение переменной? На помощь приходит знакомое по прошлому уровню замыкание (*closure*) — оно держит саму переменную, а не копию:

```go
package main

import "fmt"

func main() {
	x := 1
	defer func() {
		fmt.Println("x =", x)
	}()
	x = 2
}
```

```
x = 2
```

Сравните две формы:

| Форма | Что напечатает | Почему |
|---|---|---|
| `defer fmt.Println(x)` | значение `x` на момент `defer` | аргумент вычислен и зафиксирован сразу |
| `defer func() { fmt.Println(x) }()` | значение `x` на момент выхода | замыкание хранит переменную, а не её копию |

> [!WARNING]
> Не забудьте пару скобок `()` в конце: `defer func() { ... }()`. Мы откладываем **вызов** анонимной функции. Без скобок — ошибка компиляции.

## Зачем это в реальном коде: уборка за собой

Главное применение `defer` — освобождение ресурсов (*resource cleanup*). Открыли файл — надо закрыть, установили сетевое соединение — надо разорвать, и обязательно при любом исходе. Золотое правило Go: получил ресурс — **следующей же строкой** отложи его освобождение:

```go
func work() {
	fmt.Println("открываю соединение")
	defer fmt.Println("закрываю соединение") // сосед строки открытия

	fmt.Println("работаю с данными...")
	// сколько бы ранних return ни появилось ниже,
	// соединение гарантированно закроется
}
```

```
открываю соединение
работаю с данными...
закрываю соединение
```

Строки «открыл» и «закрыл» стоят рядом — при чтении кода сразу видно, что ресурс не утечёт. С настоящими файлами вы поработаете дальше в курсе, и там `defer file.Close()` будет в каждой второй функции.

> [!NOTE]
> Отложенные вызовы срабатывают даже при аварийном завершении функции — панике (*panic*). Ресурсы освободятся и в этом случае. Подробно про панику и восстановление — впереди.

## defer в цикле — копится до конца функции

> [!WARNING]
> `defer` привязан к **функции**, а не к блоку кода. Отложенный вызов внутри цикла не сработает в конце итерации — все вызовы накопятся и выполнятся только при выходе из функции.

```go
package main

import "fmt"

func main() {
	for i := 1; i <= 3; i++ {
		defer fmt.Println("отложили", i)
	}
	fmt.Println("цикл закончился")
}
```

```
цикл закончился
отложили 3
отложили 2
отложили 1
```

Каждая итерация положила в стопку свой вызов (с зафиксированным `i` — помните про конверт?), и вся стопка развернулась в конце `main` в обратном порядке. В маленьком цикле это безобидно, но если в цикле на тысячи итераций открывать ресурс и откладывать закрытие — все тысячи закрытий будут ждать конца функции. Лекарство — выносить тело цикла в отдельную функцию, тогда `defer` срабатывает на каждый вызов.

## defer может изменить именованный результат

Помните именованные результаты из уровня 12? Именованный результат — это переменная, и она жива в момент выполнения отложенных вызовов. Значит, `defer`-замыкание может её поменять — **после** `return`:

```go
func double(n int) (result int) {
	defer func() {
		result += 1
	}()
	result = n * 2
	return result
}

func main() {
	fmt.Println(double(5))
}
```

```
11
```

Порядок событий: `return` записывает `10` в `result` → срабатывает отложенное замыкание и делает `result` равным `11` → наружу уезжает `11`. Такой трюк работает только со связкой «именованный результат + замыкание»: обычный `return n * 2` без имени менять было бы нечего. В реальном коде так дописывают последние штрихи к ответу функции — вы попробуете это в задаче со звёздочкой.

## Типичные ошибки новичка

| Код | Что случится | Как чинить |
|---|---|---|
| `defer f` без скобок | ошибка компиляции: нужен вызов | `defer f()` |
| `defer func() { ... }` без `()` в конце | ошибка компиляции: замыкание не вызвано | добавить `()` после `}` |
| `defer` написан ниже раннего `return` | при раннем выходе вызов не зарегистрируется | ставить `defer` в начале функции |
| `defer fmt.Println(x)` в надежде на финальное `x` | напечатает `x` на момент регистрации | обернуть в замыкание: `defer func() { fmt.Println(x) }()` |
| `defer` в длинном цикле | вызовы копятся до конца функции | вынести тело итерации в отдельную функцию |
| ждать `defer` в конце блока `if` или `for` | сработает только при выходе из **функции** | помнить: единица отсчёта — функция |

## Запомнить

- `defer f(...)` откладывает вызов до выхода из функции — и срабатывает при **любом** пути выхода, через какой бы `return` функция ни ушла.
- Несколько `defer` выполняются в обратном порядке — LIFO, стопка тарелок.
- Аргументы отложенного вызова вычисляются **в момент `defer`** («в конверт»), выполняется позже только сам вызов.
- Нужно актуальное значение переменной — откладывайте замыкание: `defer func() { ... }()` (скобки вызова обязательны!).
- Главное применение — уборка за собой: получил ресурс → следующей строкой `defer` его освобождение.
- `defer` в цикле копится до конца **функции**, а не итерации.
- `defer`-замыкание успевает изменить именованный результат уже после `return`.
