# Бонус: сортировка — sort.Slice и его секрет

Отсортировать список — задача, которая встречается чаще, чем хотелось бы: игроки по очкам, товары по цене, файлы по дате. Писать сортировку руками в Go не нужно — есть пакет `sort`. А в конце урока выяснится, что весь он держится на… правильно, интерфейсе — потому этот бонус и живёт в секции про них.

## Простые случаи: sort.Ints и sort.Strings

Для слайсов чисел и строк — готовые функции:

```go
nums := []int{5, 2, 8, 1}
sort.Ints(nums)
fmt.Println(nums) // [1 2 5 8]

words := []string{"груша", "арбуз", "банан"}
sort.Strings(words)
fmt.Println(words) // [арбуз банан груша]
```

Обратите внимание: функции ничего не возвращают. Сортировка происходит **на месте** (*in place*) — меняется сам слайс. Это не копия: старого порядка больше нет.

## sort.Slice — сортируем что угодно

А если слайс структур? Числа сравнивать Go умеет, а вот кто «меньше» из двух человек — вопрос без универсального ответа: по возрасту? по имени? Критерий задаёте вы — функцией:

```go
type Person struct {
	Name string
	Age  int
}

people := []Person{
	{Name: "Оля", Age: 25},
	{Name: "Ваня", Age: 19},
	{Name: "Марк", Age: 32},
}

sort.Slice(people, func(i, j int) bool {
	return people[i].Age < people[j].Age
})
fmt.Println(people) // [{Ваня 19} {Оля 25} {Марк 32}]
```

Второй аргумент — less-функция: «правда ли, что элемент с индексом `i` должен стоять **раньше** элемента с индексом `j`?» Пакет `sort` дёргает её для разных пар индексов и расставляет элементы так, чтобы все ответы сошлись.

Приглядитесь: это же замыкание (*closure*) с уровня про функции! Анонимная функция видит слайс `people` из окружающего кода — поэтому ей достаточно двух индексов.

## По убыванию и по нескольким ключам

По убыванию? Переверните сравнение:

```go
sort.Slice(people, func(i, j int) bool {
	return people[i].Age > people[j].Age // старшие — вперёд
})
```

Несколько ключей? Сначала сравните главный; при равенстве — запасной:

```go
sort.Slice(people, func(i, j int) bool {
	if people[i].Age != people[j].Age {
		return people[i].Age < people[j].Age // главный ключ — возраст
	}
	return people[i].Name < people[j].Name // при равном возрасте — по имени
})
```

> [!WARNING]
> Less-функция должна отвечать на вопрос «строго раньше?». Никаких `<=`: для равных элементов ответ обязан быть `false`, иначе порядок станет непредсказуемым. И сравнивайте элементы, а не индексы: `people[i].Age < people[j].Age`, а не `i < j`.

## Стабильность: sort.SliceStable

Что происходит с РАВНЫМИ элементами — например, двумя людьми по 25 лет? `sort.Slice` может переставить их как угодно. Если важно сохранить исходный взаимный порядок (скажем, список уже отсортирован по имени, а вы досортировываете по возрасту) — берите `sort.SliceStable`: сигнатура та же, равные элементы гарантированно остаются в прежнем порядке. Такая сортировка называется стабильной (*stable sort*).

## Под капотом — интерфейс (конечно же)

Откуда `sort` умеет сортировать что угодно? Открываем документацию:

```go
func Sort(data Interface)

// sort.Interface:
type Interface interface {
	Len() int           // сколько элементов
	Less(i, j int) bool // должен ли i-й стоять раньше j-го
	Swap(i, j int)      // поменять i-й и j-й местами
}
```

Алгоритму сортировки не нужно знать, ЧТО он сортирует, — достаточно трёх умений: узнать длину, сравнить, поменять местами. Любой тип с этими методами сортируем. До появления `sort.Slice` (Go 1.8) писали именно так:

```go
type ByAge []Person

func (a ByAge) Len() int           { return len(a) }
func (a ByAge) Less(i, j int) bool { return a[i].Age < a[j].Age }
func (a ByAge) Swap(i, j int)      { a[i], a[j] = a[j], a[i] }

sort.Sort(ByAge(people)) // тот же результат, что sort.Slice выше
```

Именованный тип на основе слайса, три метода — и `sort.Sort` работает. В новом коде так почти не пишут (`sort.Slice` короче), но в чужих проектах `ByAge`-паттерн встречается постоянно. А для нас это идеальная иллюстрация всей секции: **маленький интерфейс превращает один алгоритм в универсальный инструмент** — ровно как `io.Writer` превращал одну функцию печати в универсальную.

> [!NOTE]
> В современных версиях Go есть и третий способ — `slices.Sort(nums)` и `slices.SortFunc` из пакета `slices`. Они построены на дженериках (*generics*), до которых вы доберётесь в своей секции. `sort.Slice` при этом никуда не делся и отлично работает.

## Типичные ошибки новичка

| Код | Что случится | Как чинить |
|---|---|---|
| `sorted := sort.Ints(nums)` | ошибка компиляции: sort.Ints ничего не возвращает | сортировка на месте: просто `sort.Ints(nums)` |
| `return people[i].Age <= people[j].Age` | контракт нарушен: для равных должно быть false; порядок непредсказуем | строгое сравнение: `<` |
| `return i < j` в less-функции | сортировка «по индексам» ничего не меняет | сравнивать элементы: `people[i].X < people[j].X` |
| ожидать, что исходный порядок сохранится | его больше нет — слайс изменён на месте | нужна копия — скопируйте до сортировки (`append([]Person{}, people...)`) |
| сортировать строки и удивляться «Яблоко» перед «арбуз» | сравнение строк — по кодам символов: заглавные раньше строчных | в less сравнивать `strings.ToLower(...)` |

## Запомнить

- `sort.Ints`, `sort.Strings` — готовые сортировки простых слайсов; работают на месте, ничего не возвращают.
- `sort.Slice(s, less)` сортирует что угодно; less-функция отвечает «должен ли i-й стоять строго раньше j-го».
- Порядок задаёте вы: `<` — по возрастанию, `>` — по убыванию; несколько ключей — сравнение главного, при равенстве запасного.
- Less — строгое сравнение: для равных элементов только `false`, никаких `<=`.
- `sort.SliceStable` сохраняет исходный порядок равных элементов.
- Под капотом — `sort.Interface` (Len/Less/Swap): три умения делают любой тип сортируемым. Маленькие интерфейсы — большая сила.
