# JSON и теги структур — данные, которые понимают все

Ваши структуры живут внутри программы. Но рано или поздно данные нужно выпустить наружу: сохранить в файл, отправить по сети, показать другой программе. Для этого нужен формат, который поймут все — и Go, и Python, и браузер. Самый распространённый такой формат — JSON (*JavaScript Object Notation*), и в стандартной библиотеке Go для него есть готовый пакет `encoding/json`.

## Как выглядит JSON

JSON — это обычный текст. Объект — пары «имя: значение» в фигурных скобках, массив — значения в квадратных:

```json
{"name": "gopher", "score": 42}
```

```json
[
  {"title": "Go для всех", "pages": 320},
  {"title": "Море и чайки", "pages": 140}
]
```

Ничего не напоминает? Объект JSON выглядит как структура Go, массив — как слайс. Это не совпадение: пакет `encoding/json` именно так их и сопоставляет.

## json.Marshal — структура → JSON

Превращение значения Go в JSON называется сериализацией (*marshalling*). Делает её функция `json.Marshal`:

```go
package main

import (
	"encoding/json"
	"fmt"
)

type Player struct {
	Name  string
	Score int
}

func main() {
	p := Player{Name: "gopher", Score: 42}
	b, err := json.Marshal(p)
	if err != nil {
		fmt.Println("ошибка:", err)
		return
	}
	fmt.Println(string(b))
}
```

```
{"Name":"gopher","Score":42}
```

Разберём по шагам:

- `json.Marshal(p)` возвращает **два** значения: срез байтов `[]byte` и ошибку — та же пара «результат + получилось ли», что у `strconv.Atoi`.
- Печатать срез байтов напрямую неудобно, поэтому его конвертируют в строку: `string(b)` — так же, как вы превращали руны в строку на уровне про строки.
- Поля идут в JSON **в порядке объявления** в структуре.

Один вопрос повис в воздухе: почему в JSON получилось `"Name"` с большой буквы? Настоящий JSON так почти никогда не пишут. Сейчас разберёмся.

## Пакет json видит только экспортированные поля

`encoding/json` — чужой пакет. А в Go действует простое правило видимости: из чужого пакета видны только **экспортированные** (*exported*) имена — те, что начинаются с большой буквы. Поэтому все функции библиотек, которыми вы пользуетесь, пишутся с заглавной: `fmt.Println`, `strings.ToUpper`, `json.Marshal`. Поля структуры — не исключение:

```go
type Player struct {
	Name  string
	score int // с маленькой буквы — для пакета json невидимо
}

p := Player{Name: "gopher", score: 99}
b, _ := json.Marshal(p)
fmt.Println(string(b))
```

```
{"Name":"gopher"}
```

> [!WARNING]
> Поле с маленькой буквы `json.Marshal` пропускает **молча**: ни ошибки компиляции, ни ошибки выполнения — поле просто исчезает из JSON. Это классическая ловушка: «почему в JSON нет половины данных?!» — проверьте первые буквы полей.

## Теги структур — свои имена для JSON

Итак, поля обязаны быть с большой буквы. Но в JSON имена традиционно строчные: `name`, `score`. Конфликт решают теги структур (*struct tags*) — подсказки, которые пишутся после типа поля в обратных кавычках:

```go
type Player struct {
	Name  string `json:"name"`
	Score int    `json:"score"`
}

p := Player{Name: "gopher", Score: 42}
b, _ := json.Marshal(p)
fmt.Println(string(b))
```

```
{"name":"gopher","score":42}
```

Тег читается как инструкция: «в JSON это поле зовут `name`». Синтаксис точен **до символа**: обратные кавычки `` ` ``, слово `json`, двоеточие без пробелов, имя в обычных кавычках.

> [!WARNING]
> Опечатка в теге — НЕ ошибка компиляции. Напишете `json: "name"` (пробел после двоеточия) или перепутаете кавычки — программа соберётся, но тег молча не сработает, и поле уедет в JSON под своим именем `Name`. Сверяйте тег с образцом посимвольно.

## json.Unmarshal — JSON → структура

Обратное превращение — десериализация (*unmarshalling*). Здесь пригодится всё, что вы узнали про указатели:

```go
data := []byte(`{"name":"gopher","score":42}`)

var p Player
err := json.Unmarshal(data, &p)
if err != nil {
	fmt.Println("ошибка:", err)
	return
}
fmt.Println(p.Name, p.Score)
```

```
gopher 42
```

Две вещи, на которые стоит посмотреть внимательно:

- Строка в **обратных кавычках** `` `...` `` — «сырая» строка: внутри неё можно писать обычные кавычки без экранирования. Для JSON-текста в коде — то, что надо. `[]byte(...)` конвертирует её в срез байтов, который и ест `Unmarshal`.
- `&p` — **указатель**! `Unmarshal` должен записать результат в вашу переменную, а для этого ему нужен её адрес. Вот зачем был уровень про указатели: передадите `p` без `&` — функция вернёт ошибку, и в структуру ничего не запишется.

Если JSON кривой (скобка потерялась, кавычка не закрыта) — `Unmarshal` вернёт ошибку, и `if err != nil` её поймает. Идиома вам знакома по `strconv.Atoi`.

> [!NOTE]
> `Unmarshal` — не строгий контролёр, а покладистый почтальон. Поле есть в структуре, но нет в JSON? Останется нулевое значение (`""`, `0`, `false`). В JSON есть лишнее поле, которого нет в структуре? Молча игнорируется. Ошибок это не вызывает.

Проверим на живом примере:

```go
data := []byte(`{"name":"gopher","level":99}`)

var p Player
json.Unmarshal(data, &p)
fmt.Println(p.Name, p.Score)
```

```
gopher 0
```

`level` из JSON никуда не попал (в структуре нет такого поля), а `Score` остался нулём (в JSON его не было).

## Рецепт: читаем JSON со стандартного ввода

В задачах JSON будет приходить через стандартный ввод. `fmt.Scan` тут не помощник: он режет ввод по пробелам, а JSON бывает и с пробелами, и на несколько строк. Запомните рецепт:

```go
package main

import (
	"encoding/json"
	"fmt"
	"os"
)

type Player struct {
	Name  string `json:"name"`
	Score int    `json:"score"`
}

func main() {
	var p Player
	dec := json.NewDecoder(os.Stdin)
	err := dec.Decode(&p)
	if err != nil {
		fmt.Println("ошибка:", err)
		return
	}
	fmt.Println(p.Name, p.Score)
}
```

Подадите на вход `{"name": "gopher", "score": 42}` — получите `gopher 42`.

Как это работает: `os.Stdin` — стандартный ввод программы (тот самый, откуда читает и `fmt.Scan`), `json.NewDecoder` строит по нему декодер, а `dec.Decode(&p)` вычитывает **один JSON целиком** — сколько бы строк он ни занимал и сколько бы пробелов в нём ни было. Указатель `&p` нужен по той же причине, что и в `Unmarshal`. Пакет `os` умеет намного больше — про файлы и аргументы командной строки поговорим позже в курсе, пока `os.Stdin` — просто часть рецепта.

## Слайс структур → JSON-массив

`Marshal` и `Decode` работают не только со структурами. Слайс структур превращается в JSON-массив:

```go
team := []Player{
	{Name: "gopher", Score: 42},
	{Name: "ferris", Score: 37},
}
b, _ := json.Marshal(team)
fmt.Println(string(b))
```

```
[{"name":"gopher","score":42},{"name":"ferris","score":37}]
```

И обратно: объявите `var team []Player` и декодируйте массив прямо в слайс — `dec.Decode(&team)`. Дальше по нему можно ходить обычным `for range`.

## MarshalIndent — JSON для людей

`json.Marshal` пишет всё в одну строку — компактно, но глазами читать тяжело. Для красивого вывода есть `json.MarshalIndent(v, префикс, отступ)`:

```go
p := Player{Name: "gopher", Score: 42}
b, _ := json.MarshalIndent(p, "", "  ")
fmt.Println(string(b))
```

```
{
  "name": "gopher",
  "score": 42
}
```

Префикс обычно пустой, отступ — два пробела. В задачах этого уровня нужен обычный `Marshal`, а `MarshalIndent` держите в голове для отладки.

> [!NOTE]
> В теге можно дописать `omitempty`: `` `json:"score,omitempty"` `` — «пропусти поле, если в нём нулевое значение». Полезно для необязательных полей; в задачах уровня не используется.

## Таблица соответствий: Go ↔ JSON

| Тип Go | Тип JSON | Пример |
|---|---|---|
| `string` | строка | `"gopher"` |
| `int`, `float64` | число | `42`, `3.14` |
| `bool` | `true` / `false` | `true` |
| слайс | массив | `[1, 2, 3]` |
| структура, карта | объект | `{"a": 1}` |
| указатель `nil` | `null` | `null` |

## Типичные ошибки новичка

| Код | Что случится | Как чинить |
|---|---|---|
| поле `score int` с маленькой буквы | молча пропадёт из JSON | экспортировать: `Score int` + тег `` `json:"score"` `` |
| `json.Unmarshal(data, p)` без `&` | ошибка, в `p` ничего не запишется | передавать указатель: `&p` |
| тег с опечаткой: `json: "name"` | компилируется, но тег не работает — в JSON уедет `Name` | сверить тег посимвольно: `` `json:"name"` `` |
| `fmt.Scan` для JSON с пробелами | прочитает кусок до первого пробела | рецепт: `json.NewDecoder(os.Stdin)` + `Decode(&v)` |
| не проверить `err` у `Decode` | кривой JSON тихо оставит нулевые значения | `if err != nil` — как с `strconv.Atoi` |

## Запомнить

- JSON — текстовый формат обмена: объект `{}` ↔ структура/карта, массив `[]` ↔ слайс.
- `json.Marshal(v)` → `[]byte` и ошибка; печатать через `string(b)`. Поля — в порядке объявления.
- Пакет `json` видит только **экспортированные** поля (с большой буквы); остальные пропадают молча.
- Имена для JSON задают теги: `` `json:"name"` `` — в обратных кавычках, точность до символа, опечатка не ловится компилятором.
- `json.Unmarshal(data, &v)` — обязательно **указатель**, иначе данные никуда не запишутся.
- Нет поля в JSON → нулевое значение; лишнее поле в JSON → игнорируется.
- Рецепт чтения из ввода: `dec := json.NewDecoder(os.Stdin)`, затем `dec.Decode(&v)` — переносы строк и пробелы декодеру не мешают.
- Красивый вывод — `json.MarshalIndent(v, "", "  ")`.
