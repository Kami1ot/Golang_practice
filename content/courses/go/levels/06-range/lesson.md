# range, break и continue — управляем циклом

На прошлом уровне вы крутили циклы «вручную»: сами заводили счётчик, сами писали условие, сами не забывали `i++`. Go умеет брать эту рутину на себя — знакомьтесь, ключевое слово `range`. А заодно разберёмся с двумя рычагами управления циклом: `break` и `continue`.

## range по числу — современный Go

Начиная с Go 1.22 (мы используем Go 1.26, так что всё в порядке) можно писать так:

```go
for i := range 5 {
    fmt.Println(i)
}
// 0
// 1
// 2
// 3
// 4
```

`range 5` выдаёт числа от `0` до `4` — ровно **5 итераций**, как `for i := 0; i < 5; i++`, только без шанса опечататься в условии или пост-действии.

> [!NOTE]
> Запомните: `range n` — это числа `0, 1, …, n−1`. Само `n` в диапазон **не входит**. Если `n = 0` (или отрицательное) — тело не выполнится ни разу. Нужны числа от 1 до n? Пишите `for i := range n { fmt.Println(i + 1) }` или по старинке `for i := 1; i <= n; i++`.

Если счётчик внутри не нужен — его можно вовсе не объявлять:

```go
for range 3 {
    fmt.Println("ку!")
}
// ку!
// ку!
// ку!
```

Это удобно, когда нужно просто «повторить n раз» — например, прочитать n чисел:

```go
var n int
fmt.Scan(&n)

sum := 0
for range n {
    var x int
    fmt.Scan(&x)
    sum += x
}
fmt.Println(sum)
```

> [!WARNING]
> В старых учебниках и видео (до 2024 года) вы `range` по числу не встретите — тогда он работал только с коллекциями, и `for i := range 10` был ошибкой компиляции `cannot range over 10`. Если видите в интернете «так нельзя» — это устаревшая информация. А вот классический `for i := 0; i < n; i++` работал и работает всегда: обе формы равноправны, выбирайте ту, что читается лучше.

## break — выйти немедленно

`break` прекращает цикл сразу, не дожидаясь, пока условие станет ложным. Выполнение продолжается с первой строки после `}` цикла:

```go
for i := range 100 {
    if i*i > 50 {
        fmt.Println("первый квадрат больше 50:", i*i)
        break // дальше искать незачем
    }
}
// первый квадрат больше 50: 64
```

Идиома «ищем и выходим» экономит время: зачем крутить сто итераций, если ответ нашёлся на восьмой?

Вторая классика — вечный цикл с выходом по событию (вы видели её на прошлом уровне):

```go
for {
    var x int
    fmt.Scan(&x)
    if x < 0 {
        break // отрицательное число — стоп-сигнал
    }
    fmt.Println("принято:", x)
}
```

## continue — пропустить итерацию

`continue` прекращает только **текущую** итерацию: всё, что ниже него, пропускается, и цикл переходит к следующему шагу.

```go
for i := range 10 {
    if i%3 != 0 {
        continue // не делится на 3 — пропускаем
    }
    fmt.Println(i)
}
// 0
// 3
// 6
// 9
```

Читается как фильтр: «если элемент не подходит — дальше». Без `continue` пришлось бы заворачивать полезный код в `if`, и при нескольких проверках лесенка вложенности быстро становится нечитаемой:

```go
// Со continue: плоско и ясно          // Без continue: лесенка
for i := range 100 {                   for i := range 100 {
    if i%2 != 0 {                          if i%2 == 0 {
        continue                               if i%7 == 0 {
    }                                              fmt.Println(i)
    if i%7 != 0 {                              }
        continue                           }
    }                                  }
    fmt.Println(i)
}
```

Оба варианта печатают 0, 14, 28, 42, 56, 70, 84, 98 — но левый расширять приятнее.

## break и continue рядом: сравним

| | `break` | `continue` |
|---|---|---|
| Что прерывает | весь цикл | только текущую итерацию |
| Куда передаёт управление | за `}` цикла | к следующей итерации (проверке условия) |
| Типичный сценарий | «нашли — выходим», стоп-сигнал | фильтрация: «не подходит — пропускаем» |

Мини-пример, где работают оба:

```go
sum := 0
for {
    var x int
    fmt.Scan(&x)
    if x == 0 {
        break // 0 — конец ввода
    }
    if x < 0 {
        continue // отрицательные не считаем
    }
    sum += x
}
fmt.Println(sum) // для ввода: 5 -2 7 -9 3 0 → выведет 15
```

> [!WARNING]
> `break` и `continue` работают только внутри цикла. Написать их в `main` вне цикла — ошибка компиляции `break is not in a loop`. А внутри `switch`, который стоит в цикле, `break` прервёт `switch`, а не цикл — имейте в виду на будущее.

## Вложенные циклы: break выходит только из внутреннего

Циклы можно вкладывать друг в друга. Важный нюанс: `break` (и `continue`) действуют на **ближайший** цикл:

```go
for i := range 3 {
    for j := range 3 {
        if j == 1 {
            break // прерывает только внутренний цикл по j
        }
        fmt.Println(i, j)
    }
}
// 0 0
// 1 0
// 2 0
```

Внешний цикл спокойно прокрутился все 3 раза. Как выпрыгнуть сразу из обоих — расскажет бонусный уровень про вложенные циклы (там есть метки и `break LABEL`).

## Тизер: range по строке

`range` умеет ходить не только по числам. Например, по строке:

```go
for i, r := range "Go!" {
    fmt.Println(i, r)
}
// 0 71
// 1 111
// 2 33
```

Числа 71, 111, 33 — это коды символов `G`, `o`, `!`. Здесь `range` выдаёт уже **две** переменные — позицию и символ (руну, *rune*). С русскими буквами появляются сюрпризы: позиции идут не подряд. Почему — узнаете на уровне про строки. А на следующем уровне `range` покажет главный талант — обход слайсов.

## Запомнить

- `for i := range n` — числа от 0 до n−1; само n не входит; при n ≤ 0 — ноль итераций.
- `for range n` — просто повторить n раз, счётчик не нужен.
- range по числу — это Go 1.22+; в старых статьях его нет, но у нас Go 1.26.
- `break` — выйти из цикла целиком; `continue` — пропустить остаток текущей итерации.
- Во вложенных циклах `break` прерывает только ближайший цикл.
- Вечный `for {}` + `break` по стоп-сигналу — стандартный способ читать данные «до особого числа».
