# Условия: if и switch

До сих пор наши программы шли по одной колее: строка за строкой, сверху вниз. Программа становится по-настоящему программой, когда начинает **принимать решения**. За это отвечают условные конструкции (*conditionals*) — тема этого уровня.

## Булев тип: истина или ложь

В основе любого решения — тип `bool` с двумя значениями: `true` (истина) и `false` (ложь). Булевы значения рождаются из **сравнений**:

```go
age := 20
fmt.Println(age >= 18)
fmt.Println(age == 100)
// Вывод:
// true
// false
```

### Операторы сравнения

| Оператор | Смысл | Пример (при `a := 5`) |
|---|---|---|
| `==` | равно | `a == 5` → `true` |
| `!=` | не равно | `a != 5` → `false` |
| `<` | меньше | `a < 10` → `true` |
| `<=` | меньше или равно | `a <= 5` → `true` |
| `>` | больше | `a > 5` → `false` |
| `>=` | больше или равно | `a >= 5` → `true` |

> [!WARNING]
> `==` сравнивает, `=` присваивает. В C путаница между ними — тихий баг, а в Go `if a = 5 {` просто не скомпилируется: «cannot use assignment a = 5 as value». Компилятор снова на вашей стороне.

### Логические операторы

Сравнения комбинируются логическими операторами (*logical operators*):

| Оператор | Название | Результат `true`, когда... |
|---|---|---|
| `&&` | И (*and*) | **оба** операнда истинны |
| `\|\|` | ИЛИ (*or*) | **хотя бы один** истинен |
| `!` | НЕ (*not*) | операнд ложен |

```go
age := 16
hasTicket := true
fmt.Println(age >= 18 && hasTicket)   // false: первое условие ложно
fmt.Println(age >= 18 || hasTicket)   // true: хватает второго
fmt.Println(!hasTicket)               // false: отрицание истины
```

### Ленивость && и ||

Go вычисляет логические выражения **лениво** (*short-circuit evaluation*): если результат уже ясен по левому операнду, правый даже не вычисляется.

- `false && что-угодно` → сразу `false`, правая часть не трогается;
- `true || что-угодно` → сразу `true`.

Это не просто оптимизация — на этом строят защитные проверки: в `b != 0 && a/b > 10` деление не выполнится при нулевом `b`, и программа не упадёт.

## if / else

Базовая форма ветвления:

```go
if age >= 18 {
    fmt.Println("Доступ разрешён")
} else {
    fmt.Println("Доступ запрещён")
}
```

Три особенности Go:

- Круглых скобок вокруг условия **нет**: `if age >= 18`, а не `if (age >= 18)`. Написать со скобками можно, но `gofmt` их уберёт — так никто не пишет.
- Фигурные скобки обязательны **всегда**, даже для одной строки.
- `{` стоит на той же строке, что и `if` / `else` — иначе ошибка компиляции (те же автоматические точки с запятой, что и в уровне 1).

`else` может отсутствовать — тогда при ложном условии просто ничего не происходит:

```go
if score > record {
    fmt.Println("Новый рекорд!")
}
```

## else if: цепочка условий

Когда вариантов больше двух, ветки выстраивают цепочкой. Проверки идут **сверху вниз**, выполняется **первая** истинная ветка — остальные пропускаются:

```go
score := 75
if score >= 90 {
    fmt.Println("отлично")
} else if score >= 60 {
    fmt.Println("зачёт")
} else {
    fmt.Println("пересдача")
}
// Вывод: зачёт
```

> [!WARNING]
> Порядок веток — часть логики! Если начать с `score >= 60`, то и 75, и 95 попадут в первую же ветку, а до «отлично» очередь никогда не дойдёт. Правило: от **частного** условия к **общему**.

## if с коротким объявлением — идиома Go

Перед условием можно объявить переменную; она видна **только** внутри `if` и его `else`:

```go
if n := len(name); n > 20 {
    fmt.Println("слишком длинное имя:", n)
} else {
    fmt.Println("ок, длина", n)
}
// здесь n уже не существует
```

Зачем это? Переменная нужна ровно для одной проверки — и она не «протекает» в остальной код, не захламляет функцию. Это идиома (*idiom*) Go: вы будете видеть её в каждом втором чужом коде, особенно при обработке ошибок (`if err := doSomething(); err != nil { ... }` — познакомимся в уровне про ошибки).

## Оператор %: остаток от деления

Оператор `%` (остаток, *modulo*) возвращает остаток от целочисленного деления. Рядом с условиями он живёт постоянно — им проверяют делимость:

```go
fmt.Println(7 % 3)   // 1  (7 = 2*3 + 1)
fmt.Println(10 % 5)  // 0  (делится нацело)
fmt.Println(4 % 2)   // 0
```

Классические проверки:

```go
if n%2 == 0 {
    fmt.Println("чётное")
}
if n%10 == 0 {
    fmt.Println("круглое")
}
```

Остаток `0` — значит, делится нацело. Запомните этот приём: он нужен в задаче этого уровня.

## switch: когда веток много

Длинная цепочка `else if` по одному значению читается тяжело. `switch` — то же самое, но глазам легче:

```go
switch day {
case "сб", "вс":
    fmt.Println("выходной")
case "пн":
    fmt.Println("тяжёлый день")
default:
    fmt.Println("будний день")
}
```

Что здесь важно:

- В одном `case` можно перечислить **несколько значений** через запятую.
- `default` срабатывает, если не подошёл ни один `case` (он необязателен).
- **`break` писать не нужно**: Go выполняет одну ветку и выходит из `switch` сам.

> [!NOTE]
> В C/Java после каждого `case` нужен `break`, иначе выполнение «проваливается» в следующую ветку. В Go всё наоборот: проваливания нет по умолчанию, а для редких случаев, когда оно правда нужно, есть ключевое слово `fallthrough`. За годы Go-практики оно может не встретиться вам ни разу — просто знайте, что оно существует.

### switch без выражения

Если убрать выражение после `switch`, ветки превращаются в произвольные условия — это элегантная замена цепочке `else if`:

```go
switch {
case score >= 90:
    fmt.Println("отлично")
case score >= 60:
    fmt.Println("зачёт")
default:
    fmt.Println("пересдача")
}
```

Работает так же: сверху вниз, первая истинная ветка, автоматический выход. И так же важен порядок: от частного к общему.

## Вложенность и ранний выход

Условия можно вкладывать друг в друга, но глубокая лесенка быстро становится нечитаемой:

```go
// тяжело читать:
if user != "" {
    if age >= 18 {
        if hasTicket {
            fmt.Println("проходите")
        }
    }
}
```

Идиоматичный Go предпочитает **ранний выход** (*early return*): проверяем «плохие» случаи первыми и сразу выходим, а «счастливый путь» остаётся не вложенным:

```go
if user == "" {
    fmt.Println("нет имени")
    return          // выходим из функции немедленно
}
if age < 18 {
    fmt.Println("слишком юн")
    return
}
fmt.Println("проходите")
```

`return` завершает функцию сразу; в `func main` это означает конец программы. Читается как список правил: «нет имени — до свидания; молод — до свидания; иначе — проходите».

## Типичные ошибки новичка

### 1. Скобка на новой строке

```go
if x > 0
{
    fmt.Println("плюс")
}
```

```
syntax error: unexpected newline, expected { after if clause
```

**Как чинить:** `{` — на строке условия. Всегда.

### 2. Не-булево условие

Привычка из Python/C — «число само по себе истинно»:

```go
n := 5
if n {
    fmt.Println("не ноль")
}
```

```
non-boolean condition in if statement
```

**Почему:** в Go условие обязано быть типа `bool`. **Как чинить:** пишите сравнение явно — `if n != 0`.

### 3. Перепутанный порядок веток

Код компилируется, но работает неверно — самый коварный вид ошибки:

```go
score := 95
if score >= 60 {
    fmt.Println("зачёт")      // 95 попал сюда!
} else if score >= 90 {
    fmt.Println("отлично")    // недостижимо
}
// Вывод: зачёт
```

**Как чинить:** упорядочить условия от частного к общему: сначала `>= 90`, потом `>= 60`. Компилятор такое не ловит — только внимательность (и тесты).

## Запомнить

- `bool` — два значения: `true` / `false`; условие в `if` обязано быть булевым.
- Сравнения: `==`, `!=`, `<`, `<=`, `>`, `>=`. Не путать `==` (сравнить) и `=` (присвоить).
- Логика: `&&` (и), `||` (или), `!` (не); `&&` и `||` ленивы — правая часть вычисляется только при необходимости.
- `if` — без круглых скобок, но фигурные обязательны, `{` на той же строке.
- Цепочка `else if` выполняет первую истинную ветку; порядок — от частного к общему.
- `if x := ...; условие` — короткое объявление: переменная живёт только внутри if/else. Идиома Go.
- `n % m` — остаток от деления; `n%2 == 0` — проверка чётности, `n%m == 0` — кратности.
- `switch` не требует `break`; в `case` можно несколько значений; `switch` без выражения = красивый `else if`.
- Глубокой вложенности предпочитайте ранний выход: `return` в «плохих» ветках.
