# Файлы: os и bufio

До сих пор ваши программы жили одним запуском: всё, что они считали и накопили, исчезало вместе с процессом. Настоящим программам нужна память подлиннее — конфиги, логи, отчёты, сохранения. Всё это — файлы (*files*). Хорошая новость: половину темы вы уже знаете. Помните уровень про `io.Reader` и `io.Writer`? Открытый файл — это и читатель, и писатель, так что весь арсенал — `io.Copy`, `fmt.Fprintln`, `io.ReadAll` — заработает с файлами без единой новой идеи. Останется добавить пакет `bufio` — и вы во всеоружии.

## Простой путь: os.ReadFile и os.WriteFile

Когда файл небольшой, проще всего забрать его целиком:

```go
data, err := os.ReadFile("config.txt") // data — []byte, весь файл разом
if err != nil {
	fmt.Println("не прочитали:", err)
	return
}
fmt.Println(string(data)) // байты → строка, знакомая конверсия
```

`os.ReadFile` сам открывает файл, читает до конца и закрывает — никакой возни с ресурсами. Зеркальная операция — записать срез байтов в файл:

```go
err := os.WriteFile("hello.txt", []byte("привет, диск!\n"), 0644)
if err != nil {
	fmt.Println("не записали:", err)
}
```

Если файла нет — он создастся; если есть — перезапишется целиком. Третий аргумент `0644` — права доступа (*file permissions*) в восьмеричной записи: владелец читает и пишет, остальные только читают. Это юниксовская традиция; для текстовых файлов пишите `0644` не задумываясь. На Windows права почти полностью игнорируются — но писать их всё равно нужно, параметр обязательный.

## Когда файла нет: ошибки файловых операций

Файловые операции срываются постоянно: файл удалили, путь опечатан, кончились права. Поэтому здесь особенно важна дисциплина из секции про ошибки — проверять `err` и не терять причину:

```go
data, err := os.ReadFile(path)
if err != nil {
	return fmt.Errorf("читаем конфиг %s: %w", path, err)
}
```

Частый особый случай — «файла просто нет». Его распознают через `errors.Is` и ошибку-маркер `fs.ErrNotExist` из пакета `io/fs`:

```go
data, err := os.ReadFile("cache.txt")
if errors.Is(err, fs.ErrNotExist) {
	fmt.Println("кэша ещё нет — начнём с чистого листа")
	data = []byte{}
} else if err != nil {
	return err // другая беда: права, диск…
}
```

Заметьте: `%w`-обёртки этой проверке не мешают — `errors.Is` разматывает цепочку, как вы помните с уровня про обёртывание.

> [!WARNING]
> Не проверяйте результат чтения через `data == nil` или `len(data) == 0` — пустой файл читается без ошибки, а ошибка может прийти и с непустыми данными. Единственный честный индикатор беды — `err`.

## Файл как объект: os.Open и defer Close

`ReadFile` хорош, пока файл помещается в память. Для всего остального файл открывают как объект:

```go
f, err := os.Open("data.txt") // только чтение
if err != nil {
	return err
}
defer f.Close() // СРАЗУ после проверки ошибки
```

`os.Open` возвращает `*os.File` — и вот он, момент истины: **`*os.File` реализует `io.Reader`**. Та таблица с уровня про потоки не врала. Открытый файл можно отдать куда угодно, где ждут читателя:

```go
io.Copy(os.Stdout, f)  // перелить файл в терминал
data, err := io.ReadAll(f) // или выпить до дна
```

Открытый файл — ресурс операционной системы, его обязательно возвращают через `Close`. Идиома железная: **`defer f.Close()` в строке, следующей за проверкой ошибки**. Раньше нельзя — при неудачном `Open` закрывать нечего (`f` — `nil`); позже опасно — между `Open` и `Close` может вклиниться `return`, и файл «утечёт». `defer` с уровня про отложенные вызовы гарантирует закрытие при любом выходе из функции.

Для записи файл создают:

```go
f, err := os.Create("report.txt") // создать или обнулить существующий
if err != nil {
	return err
}
defer f.Close()

fmt.Fprintln(f, "Отчёт за июль")   // *os.File — это и io.Writer!
fmt.Fprintf(f, "строк: %d\n", 42)
```

`fmt.Fprintln` в файл — ровно та же функция, которой вы писали в `bytes.Buffer` и `os.Stdout`. Куда сказали — туда и пишет.

## Построчное чтение: bufio.Scanner

Лог-файл на десять гигабайт через `ReadFile` не прочитаешь — память кончится раньше. Да и зачем: чаще всего файл нужен **построчно**. Для этого в пакете `bufio` (*buffered I/O* — буферизованный ввод-вывод) живёт сканер:

```go
f, err := os.Open("access.log")
if err != nil {
	return err
}
defer f.Close()

sc := bufio.NewScanner(f)
for sc.Scan() {              // true, пока есть строки
	line := sc.Text()        // текущая строка, уже без \n
	fmt.Println("→", line)
}
if err := sc.Err(); err != nil { // проверка ПОСЛЕ цикла
	return err
}
```

Ритм такой: `Scan` читает следующую строку и говорит, получилось ли; `Text` отдаёт её без перевода строки; когда строки кончились, `Scan` возвращает `false` — цикл выходит сам. Конец файла — не ошибка, поэтому после цикла спрашивают `sc.Err()`: `nil` — дочитали честно, не `nil` — чтение оборвалось на середине.

Сканер принимает **любой** `io.Reader` — и это отличный способ поиграть с ним без файлов:

```go
sc := bufio.NewScanner(strings.NewReader("раз\nдва\nтри"))
n := 0
for sc.Scan() {
	n++
	fmt.Println(n, sc.Text())
}
// 1 раз
// 2 два
// 3 три
```

Тот же трюк с `os.Stdin` — и программа читает построчно с клавиатуры до конца ввода (*EOF*). Так вы наконец сможете прочитать строку **с пробелами**, на чём `fmt.Scan` спотыкался:

```go
sc := bufio.NewScanner(os.Stdin)
for sc.Scan() {
	fmt.Println("вы сказали:", sc.Text())
}
```

> [!NOTE]
> По умолчанию сканер рассчитан на строки до 64 КБ — для уроков, логов и конфигов хватает с запасом. Упрётесь в предел на экзотическом файле — вспомните, что у сканера есть метод `Buffer` для расширения.

## Буферизованная запись: bufio.NewWriter

Каждая запись в файл — системный вызов (*syscall*), поход к операционной системе. Писать в цикле по чуть-чуть — как ездить в магазин за каждой спичкой отдельно. `bufio.NewWriter` ставит между вами и файлом буфер: мелкие записи копятся в памяти и уезжают на диск крупными партиями:

```go
f, err := os.Create("numbers.txt")
if err != nil {
	return err
}
defer f.Close()

w := bufio.NewWriter(f)
for i := 1; i <= 1000; i++ {
	fmt.Fprintln(w, i) // пишем в буфер — быстро
}
w.Flush() // ОБЯЗАТЕЛЬНО: вытолкнуть остаток буфера в файл
```

`Flush` — критическая строчка. Без него хвост данных (всё, что не набралось на полную партию) так и останется в памяти и до файла не доедет. Программа отработает без единой ошибки — а файл окажется обрезанным или пустым.

## Дозапись в конец: os.OpenFile

`Create` обнуляет файл — для лога это катастрофа. Дописывать в конец позволяет универсальный `os.OpenFile` с флагами:

```go
f, err := os.OpenFile("app.log", os.O_APPEND|os.O_CREATE|os.O_WRONLY, 0644)
if err != nil {
	return err
}
defer f.Close()

fmt.Fprintln(f, "сервер запущен")
```

Флаги склеиваются через `|`: `O_APPEND` — писать в конец, `O_CREATE` — создать, если файла нет, `O_WRONLY` — открыть только на запись. Кстати, `os.Open` и `os.Create` — просто удобные сокращения над `OpenFile` с готовыми наборами флагов.

## Пути: filepath.Join

На Linux разделитель пути — `/`, на Windows — `\`. Склеивать пути строками — прямой путь к программе, которая работает «только у меня». Пакет `path/filepath` собирает пути правильно для текущей системы:

```go
path := filepath.Join("data", "reports", "july.txt")
// Windows: data\reports\july.txt
// Linux:   data/reports/july.txt
```

`filepath.Join` заодно причёсывает лишние разделители и точки. Любой путь, который собирается из кусочков, — только через него.

## Какой инструмент когда

| Задача | Инструмент |
|---|---|
| прочитать небольшой файл целиком | `os.ReadFile` |
| записать данные одним махом | `os.WriteFile` |
| пройти большой файл строка за строкой | `os.Open` + `bufio.Scanner` |
| много мелких записей подряд | `os.Create` + `bufio.NewWriter` + `Flush` |
| дописать в конец (лог, журнал) | `os.OpenFile` с `O_APPEND\|O_CREATE\|O_WRONLY` |
| собрать путь из частей | `filepath.Join` |

## Типичные ошибки новичка

| Код | Что случится | Как чинить |
|---|---|---|
| `os.Open` без `defer f.Close()` | файл-ресурс утекает; на Windows его вдобавок не удалить, пока открыт | `defer f.Close()` сразу после проверки err |
| `defer f.Close()` ДО проверки err | при неудачном Open закрываем nil — бессмыслица, маскирующая ошибку | сначала `if err != nil`, потом defer |
| `os.ReadFile` на гигантском файле | вся память под один файл, программа умирает | `os.Open` + `bufio.Scanner` построчно |
| `bufio.NewWriter` без `Flush` | хвост данных остаётся в буфере — файл обрезан без всяких ошибок | `w.Flush()` (или `defer w.Flush()`) в конце |
| проверка `data == nil` вместо `err` | пустой файл — не ошибка, а ошибка — не всегда nil-данные | всегда проверять именно `err` |
| `sc.Err()` не проверен после цикла | оборванное чтение неотличимо от честного конца файла | `if err := sc.Err(); err != nil` после `for` |
| пути через `path + "/" + name` | на другой ОС разделитель другой — путь не найдётся | `filepath.Join(path, name)` |

## Запомнить

- `os.ReadFile(path)` → `[]byte` целиком; `os.WriteFile(path, data, 0644)` — записать разом. Для небольших файлов — это всё, что нужно.
- «Файла нет» проверяют через `errors.Is(err, fs.ErrNotExist)` (пакет `io/fs`); обёртки `%w` проверке не мешают.
- `os.Open` → `*os.File`, который и `io.Reader`, и (после `os.Create`) `io.Writer`; `defer f.Close()` — сразу после проверки ошибки, всегда.
- Построчно: `sc := bufio.NewScanner(f)` → `for sc.Scan()` → `sc.Text()` → после цикла `sc.Err()`. Работает с любым Reader: файл, `os.Stdin`, `strings.NewReader`.
- Много мелких записей — через `bufio.NewWriter` и обязательный `Flush` в конце.
- Дозапись — `os.OpenFile(path, os.O_APPEND|os.O_CREATE|os.O_WRONLY, 0644)`.
- Пути собирает `filepath.Join` — кроссплатформенно и без ручных разделителей.
