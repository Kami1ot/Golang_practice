# Проектирование ошибок: sentinel и типы с данными

Создавать ошибки вы умеете тремя способами: `errors.New`, `fmt.Errorf` и собственный тип с методом `Error()`. Вопрос уровня — не «как создать», а **как спроектировать**: чтобы вызывающий код мог не просто напечатать ошибку, а осмысленно на неё отреагировать. Для этого в Go два инструмента: ошибки-значения (*sentinel errors*) и ошибки-типы.

## Предел одноразовых ошибок

`fmt.Errorf("возраст %d вне диапазона", n)` — отличное сообщение для человека. Но программе с ним делать нечего: как вызывающему коду понять, что случилось именно «вне диапазона», а не «не число»? Сравнивать текст?

```go
if err.Error() == "возраст 200 вне диапазона" { // НЕ ДЕЛАЙТЕ ТАК
```

Хрупко до слёз: чуть поменяли формулировку или число — проверка молча сломалась. Нужны ошибки, которые можно **узнавать**.

## Sentinel: ошибка-значение

Сигнальная ошибка (*sentinel error*) — заранее объявленное значение уровня пакета:

```go
var ErrNotFound = errors.New("запись не найдена")

func Find(id int) (User, error) {
	u, ok := db[id]
	if !ok {
		return User{}, ErrNotFound // возвращаем именно ЕЁ, всегда одну и ту же
	}
	return u, nil
}
```

Вызывающий узнаёт её через `errors.Is` — даже сквозь обёртки:

```go
user, err := Find(42)
if errors.Is(err, ErrNotFound) {
	fmt.Println("такого пользователя нет — предложим регистрацию")
	return
}
```

«Не найдено» здесь — не катастрофа, а **ожидаемая ситуация**, на которую у кода есть отдельный план. Ровно так работают знаменитые sentinel стандартной библиотеки: `io.EOF` («поток кончился» — помните уровень про Reader?) и `sql.ErrNoRows`.

> [!WARNING]
> Sentinel обязан быть ОДНИМ значением. Если писать `return errors.New("запись не найдена")` в теле функции, каждый вызов создаст **новую** ошибку: текст тот же, значение — другое, и `errors.Is` ничего не найдёт. `errors.New` сравнивается по идентичности значения, не по тексту. Поэтому — `var ErrNotFound = ...` один раз на уровне пакета.

## Ошибка-тип: когда нужны данные

Sentinel отвечает только на вопрос «ЧТО случилось». Если вызывающему нужны подробности — сколько, где, какое поле, — заводите структуру:

```go
type QuotaError struct {
	Used, Limit int
}

func (e QuotaError) Error() string {
	return fmt.Sprintf("квота исчерпана: %d из %d", e.Used, e.Limit)
}

func Upload(used, limit, size int) error {
	if used+size > limit {
		return QuotaError{Used: used + size, Limit: limit}
	}
	return nil
}
```

Наверху подробности достаёт `errors.As`:

```go
err := Upload(90, 100, 25)

var qe QuotaError
if errors.As(err, &qe) {
	fmt.Printf("не хватило %d МБ\n", qe.Used-qe.Limit) // не хватило 15 МБ
}
```

Данные пережили путешествие наверх в целости — никакого разбора текста.

## Обёртки дружат с обоими

Всё с прошлого уровня остаётся в силе: слои контекста не мешают узнаванию.

```go
err := fmt.Errorf("загрузка аватара: %w", Upload(90, 100, 25))

var qe QuotaError
fmt.Println(errors.As(err, &qe)) // true — тип найден сквозь обёртку
fmt.Println(err)                 // загрузка аватара: квота исчерпана: 115 из 100
```

Поэтому проектировать ошибки и оборачивать их — не конкурирующие техники, а две половины одной системы: внизу создают узнаваемую ошибку, по дороге добавляют контекст, наверху узнают через `Is`/`As`.

## Выбор инструмента

| Ситуация | Инструмент |
|---|---|
| наверху ошибку только напечатают | `fmt.Errorf` на месте — и хватит |
| вызывающий должен РАЗЛИЧАТЬ ситуации («не найдено» vs «нет прав») | sentinel: `var ErrX = errors.New(...)` |
| вызывающему нужны ДАННЫЕ (числа, имена, адреса) | свой тип + `errors.As` |

Идти по таблице сверху вниз: не плодите sentinel «на всякий случай» — каждый из них становится частью договора пакета, который потом неудобно менять.

## Конвенции имён

- Ошибки-значения: префикс `Err` — `ErrNotFound`, `ErrPermission`, `io.EOF` (историческое исключение).
- Ошибки-типы: суффикс `Error` — `QuotaError`, `ValidationError`, `*os.PathError`.
- Экспорт имеет значение: `ErrNotFound` с большой буквы виден из других пакетов — это публичный API; `errNotFound` — внутренняя кухня.
- Тексты, как всегда: с маленькой буквы, без точки.

## Типичные ошибки новичка

| Код | Что случится | Как чинить |
|---|---|---|
| `if err.Error() == "не найдено"` | сломается при первом изменении текста | sentinel + `errors.Is` |
| `errors.New` в теле функции как «sentinel» | каждый вызов — новое значение, errors.Is не узнаёт | одно `var ErrX = ...` на уровне пакета |
| структура ошибки без метода `Error()` | тип не error — не скомпилируется в `return` | добавить `Error() string` |
| данные в тексте: `fmt.Errorf("квота %d из %d", u, l)` — а наверху их парсят из строки | хрупкий разбор текста регулярками | тип с полями + `errors.As` |
| sentinel на каждую мелочь | раздутый публичный API, который страшно менять | по таблице выбора: сначала Errorf, потом sentinel |

## Запомнить

- Sentinel — `var ErrX = errors.New("...")` на уровне пакета: одна известная ошибка-значение; узнаётся `errors.Is`.
- `errors.New` внутри функции — всегда НОВОЕ значение: как sentinel не работает.
- Нужны данные внутри ошибки — свой тип с `Error() string`; наверху достают `errors.As(err, &e)`.
- Обёртки `%w` не мешают: Is и As видят сквозь слои.
- Выбор: печатают → Errorf; различают → sentinel; читают данные → тип.
- Имена: значения `ErrX`, типы `XError`; экспортированные ошибки — часть API пакета.
