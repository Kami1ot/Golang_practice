# Оборачивание ошибок — матрёшка с памятью

На прошлом уровне ошибки пробрасывались наверх как есть: `return 0, err`. Работает, но у длинных цепочек вызовов есть беда: наверх доезжает голое сообщение с самого дна — «invalid syntax» — а ГДЕ и ПРИ ЧЁМ это случилось, уже не видно. Оборачивание (*wrapping*) решает это красиво: каждый уровень добавляет свой контекст, не теряя исходную ошибку внутри.

## Проблема: контекст теряется по дороге

Представьте цепочку: `main → loadConfig → readFile`. Самая глубокая функция вернула «файл не найден». После двух голых пробрасываний в `main` приезжает… «файл не найден». Какой файл? При загрузке чего? Пользователь и логи в недоумении.

Можно склеить новый текст: `fmt.Errorf("загрузка конфига: %v", err)` — читается лучше, но теперь беда другая: **исходная ошибка растворилась в строке**. Программно узнать, что внутри был именно «файл не найден», больше нельзя.

## %w: оборачиваем, не теряя

У `fmt.Errorf` есть специальный глагол `%w` (*wrap*). Текст получается такой же, как с `%v`, но новая ошибка **запоминает вложенную**:

```go
var ErrNotFound = errors.New("файл не найден")

func loadConfig(path string) error {
	err := readFile(path) // вернула ErrNotFound
	if err != nil {
		return fmt.Errorf("загрузка конфига %s: %w", path, err)
	}
	return nil
}

err := loadConfig("app.json")
fmt.Println(err) // загрузка конфига app.json: файл не найден
```

Каждый уровень цепочки добавляет свою часть — сообщения читаются как путь ошибки сверху вниз: `обработка запроса: загрузка конфига app.json: файл не найден`. Конвенция оформления: `"контекст: %w"` — двоеточие и пробел.

## errors.Is: поиск по всей цепочке

Раз ошибка обёрнута, наивное сравнение ломается:

```go
err := loadConfig("app.json")

fmt.Println(err == ErrNotFound)          // false! err — обёртка, а не сам ErrNotFound
fmt.Println(errors.Is(err, ErrNotFound)) // true — Is разворачивает матрёшку
```

`errors.Is(err, target)` спрашивает: «есть ли `target` ГДЕ-ТО в цепочке err?» — и честно проверяет каждый слой. Правило простое: **сравниваете ошибку с известной — всегда `errors.Is`, никогда `==`**. Даже если сегодня обёрток нет, завтра кто-то добавит — и `==` молча сломается.

## errors.As: достать типизированную ошибку

Вы умеете делать ошибки-структуры с данными внутри (`LengthError` с уровня про Stringer). Как достать такую из цепочки? Type assertion по обёртке не сработает — нужен `errors.As`:

```go
type HTTPError struct {
	Code int
	URL  string
}

func (e HTTPError) Error() string {
	return fmt.Sprintf("запрос %s: статус %d", e.URL, e.Code)
}

// где-то глубоко:
err := fmt.Errorf("синхронизация: %w", HTTPError{Code: 404, URL: "/api/users"})

var httpErr HTTPError
if errors.As(err, &httpErr) { // ВАЖНО: указатель!
	fmt.Println(httpErr.Code) // 404 — поля снова доступны
}
```

`errors.As(err, &target)` идёт по цепочке и, найдя ошибку нужного типа, копирует её в `target` и возвращает `true`. Это `assertion + Unwrap` в одном флаконе. Не забудьте амперсанд: `As` должен ЗАПИСАТЬ найденное в вашу переменную, поэтому ему нужен её адрес — привет, уровень про указатели.

## %v против %w: одна буква — разное будущее

Текст у обоих одинаковый. Разница — в памяти:

```go
e1 := fmt.Errorf("шаг A: %v", ErrNotFound) // склеил ТЕКСТ, исходная потеряна
e2 := fmt.Errorf("шаг B: %w", ErrNotFound) // обернул, исходная внутри

fmt.Println(errors.Is(e1, ErrNotFound)) // false
fmt.Println(errors.Is(e2, ErrNotFound)) // true
```

| | `%v` | `%w` |
|---|---|---|
| Текст сообщения | одинаковый | одинаковый |
| Исходная ошибка | потеряна | сохранена в цепочке |
| `errors.Is` / `errors.As` | не найдут | найдут |
| Когда использовать | исходная ошибка дальше никому не нужна | по умолчанию для пробрасывания с контекстом |

## errors.Unwrap: как устроена матрёшка

Под капотом всё просто: обёртка умеет отдавать вложенную ошибку.

```go
wrapped := fmt.Errorf("внешний слой: %w", ErrNotFound)

fmt.Println(errors.Unwrap(wrapped) == ErrNotFound) // true
fmt.Println(errors.Unwrap(ErrNotFound))            // <nil> — дно матрёшки
```

`errors.Is` и `errors.As` — это цикл по `Unwrap` до дна. В повседневном коде `Unwrap` руками почти не зовут — но знать механизм полезно: никакой магии, обычные значения и цикл.

## Когда оборачивать, а когда нет

- **Оборачивайте**, когда добавляете полезный контекст: что делали, с каким файлом/id/URL. `fmt.Errorf("чтение %s: %w", path, err)` — золотой стандарт.
- **Пробрасывайте голым** (`return err`), когда добавить нечего: тонкие функции-переходники не обязаны множить слова.
- **Не оборачивайте пустословием**: `fmt.Errorf("ошибка: %w", err)` не добавляет ничего — наверху вырастет бессмысленное «ошибка: ошибка: ошибка: …».

## Типичные ошибки новичка

| Код | Что случится | Как чинить |
|---|---|---|
| `err == ErrNotFound` для обёрнутой ошибки | false: обёртка — другое значение | `errors.Is(err, ErrNotFound)` |
| `errors.As(err, httpErr)` без `&` | паника: As требует указатель на переменную-приёмник | `errors.As(err, &httpErr)` |
| `fmt.Errorf("контекст: %v", err)` при пробрасывании | цепочка оборвана: Is и As наверху ослепли | глагол `%w` |
| `fmt.Errorf("%w", err)` | обёртка без контекста — шум вместо пользы | добавить смысл или пробросить голым `return err` |
| проверка текста: `strings.Contains(err.Error(), "не найден")` | хрупко: чуть изменился текст — сломалось | `errors.Is` с ошибкой-значением |

## Запомнить

- `%w` в `fmt.Errorf` оборачивает: текст как у `%v`, но исходная ошибка сохраняется в цепочке.
- Конвенция: `fmt.Errorf("что делали с чем: %w", err)` — каждый слой добавляет контекст.
- `errors.Is(err, target)` — «есть ли target в цепочке?»; после появления обёрток `==` врёт.
- `errors.As(err, &typedErr)` — достать из цепочки ошибку конкретного типа; обязательно указатель.
- `%v` рвёт цепочку — используйте, только если исходная ошибка дальше никому не нужна.
- `errors.Unwrap` снимает один слой; Is/As — просто цикл по Unwrap.
- Оборачивайте с пользой: контекст без пустословия; нечего добавить — пробрасывайте как есть.
