# fmt.Stringer и error — два интерфейса, на которых стоит Go

На прошлом уровне вы узнали, что интерфейс — это контракт из методов, а реализация — неявная. Теперь познакомимся с двумя самыми знаменитыми контрактами стандартной библиотеки. Один учит тип красиво печататься (`fmt.Stringer`), второй — сообщать о неудаче (`error`). Оба крошечные, по одному методу, — та самая идиома маленьких интерфейсов.

## Как структура печатается по умолчанию

```go
type Point struct {
	X, Y int
}

p := Point{X: 3, Y: 4}
fmt.Println(p) // {3 4}
```

`{3 4}` — честно, но не для людей: ни имён полей, ни оформления. Хочется, чтобы точка печаталась как `(3; 4)`, температура — как `36.6°C`, деньги — как `1 250 ₽`. Для этого в пакете `fmt` объявлен интерфейс:

```go
// Уже объявлен в пакете fmt — писать это самим не нужно:
type Stringer interface {
	String() string
}
```

## Учим тип представляться

Реализуем контракт — как обычно, неявно, просто написав метод:

```go
func (p Point) String() string {
	return fmt.Sprintf("(%d; %d)", p.X, p.Y)
}

p := Point{X: 3, Y: 4}
fmt.Println(p)              // (3; 4)
fmt.Printf("точка: %v\n", p) // точка: (3; 4)
```

Что произошло? Функции пакета `fmt` перед печатью проверяют: «а не реализует ли это значение `Stringer`?» Реализует — значит, у типа есть своё мнение о том, как выглядеть, и `fmt` вызывает его `String()` вместо стандартного `{3 4}`. Мы не сообщали пакету `fmt` о типе `Point` ничего — сработала неявная реализация с прошлого уровня.

`fmt.Sprintf` вы помните с уровня про форматированный вывод: те же глаголы, что у `Printf`, только результат возвращается строкой — идеально для сборки `String()`.

## Stringer работает на любом именованном типе

Методы вешаются не только на структуры — и `String()` не исключение:

```go
type Celsius float64

func (c Celsius) String() string {
	return fmt.Sprintf("%.1f°C", float64(c))
}

t := Celsius(36.6)
fmt.Println(t)                  // 36.6°C
fmt.Println(Celsius(-7.25))     // -7.2°C (%.1f округляет)
```

Обратите внимание на `float64(c)` внутри метода — это не случайность, а страховка. Какая — через минуту.

Срабатывает `String()` в `Println`, `Print`, `Sprintf` и в глаголах `%v` и `%s`. А вот числовые глаголы печатают «сырое» значение:

```go
fmt.Printf("%v\n", t) // 36.6°C  — Stringer
fmt.Printf("%f\n", t) // 36.600000 — число как число
```

> [!WARNING]
> Ловушка-рекурсия. Напишите внутри `String()` вызов `fmt.Sprintf("%v", c)` — и `%v` снова позовёт `String()`, тот снова `%v`… Программа упадёт с переполнением стека (*stack overflow*). Поэтому внутри `String()` печатайте либо через конвертацию к базовому типу (`float64(c)`), либо отдельные поля (`p.X`, `p.Y`) — они-то Stringer не реализуют.

## error — это просто интерфейс

Второй герой встроен прямо в язык:

```go
// Тип error — на самом деле вот такой интерфейс:
type error interface {
	Error() string
}
```

Никакой магии: ошибка в Go — любое значение с методом `Error() string`. Функция, у которой что-то может не получиться, возвращает `error` **последним** результатом:

```go
import "errors"

func Halve(n int) (int, error) {
	if n%2 != 0 {
		return 0, errors.New("число нечётное")
	}
	return n / 2, nil
}
```

Здесь всё уже знакомое: множественный возврат — с уровня про функции, `errors.New` — фабрика простейшей ошибки с текстом, а `nil` вы видели как нулевое значение интерфейса. Пустой интерфейс ошибки означает «всё получилось».

Вызывающая сторона смотрит, что вернулось:

```go
half, err := Halve(10)
if err != nil {
	fmt.Println("не получилось:", err)
} else {
	fmt.Println(half) // 5
}

_, err = Halve(7)
fmt.Println(err) // число нечётное
```

`fmt.Println(err)` печатает текст ошибки сам — функции `fmt` понимают значения с методом `Error()` так же, как и `Stringer`.

> [!NOTE]
> Идиома `if err != nil` — визитная карточка Go: ошибки не выбрасываются, как исключения в других языках, а возвращаются и проверяются явно. Целая секция «Обработка ошибок» впереди; сегодня важно одно — `error` устроен как обычный интерфейс, и вы уже знаете, как он работает.

## Свой тип ошибки

Раз `error` — интерфейс, то СВОЙ тип с методом `Error() string` — полноценная ошибка. Зачем? Чтобы ошибка несла не только текст, но и данные:

```go
type OutOfRange struct {
	Value, Min, Max int
}

func (e OutOfRange) Error() string {
	return fmt.Sprintf("значение %d вне диапазона [%d, %d]", e.Value, e.Min, e.Max)
}

func CheckAge(age int) error {
	if age < 0 || age > 150 {
		return OutOfRange{Value: age, Min: 0, Max: 150}
	}
	return nil
}
```

Проверяем:

```go
fmt.Println(CheckAge(200)) // значение 200 вне диапазона [0, 150]
fmt.Println(CheckAge(30))  // <nil>
```

Структура `OutOfRange` спокойно уехала в интерфейсную переменную `error` — ровно так же, как `Rect` уезжал в `Shape`. А поля `Value`, `Min`, `Max` остались внутри: на уровне про type assertion вы научитесь доставать их обратно.

## Stringer и error рядом

| | `fmt.Stringer` | `error` |
|---|---|---|
| Метод контракта | `String() string` | `Error() string` |
| Смысл | «как я выгляжу» | «что пошло не так» |
| Кто обычно вызывает метод | пакет `fmt` — автоматически | код с `if err != nil` и пакет `fmt` |
| Где объявлен | пакет `fmt` | встроен в язык |

Похожи как близнецы — и оба демонстрируют силу неявной реализации: ваши типы встраиваются в стандартную библиотеку без единой строчки «регистрации».

## Типичные ошибки новичка

| Код | Что случится | Как чинить |
|---|---|---|
| `fmt.Sprintf("%v", c)` внутри `String()` типа `c` | бесконечная рекурсия, падение со stack overflow | конвертировать к базовому типу: `float64(c)` |
| метод назвали `ToString()` | `fmt` его не увидит — контракт требует именно `String()` | переименовать в `String() string` |
| `String() (string, error)` | сигнатура не совпала — тип НЕ Stringer, печать по умолчанию | вернуть ровно одну строку |
| функция возвращает `error` первым результатом | компилируется, но ломает идиому — весь Go ждёт ошибку последней | `func F() (int, error)`, не наоборот |
| `return OutOfRange{}` при УСПЕХЕ (вместо nil) | вызывающий увидит err != nil и решит, что всё сломалось | успех — это всегда `return ..., nil` |
| `Error() string` не написан, а тип возвращают как error | ошибка компиляции: тип does not implement error | добавить метод `Error() string` |

## Запомнить

- `fmt.Stringer` — интерфейс с одним методом `String() string`; реализовали — и `fmt.Println` печатает тип по-вашему.
- Внутри `String()` не форматируйте сам объект через `%v` — рекурсия; печатайте базовый тип или отдельные поля.
- `Stringer` срабатывает на `%v`, `%s`, `Println`; числовые глаголы (`%f`, `%d`) печатают сырое значение.
- `error` — встроенный интерфейс с методом `Error() string`; ошибка — обычное значение, никакой магии.
- Функция возвращает `error` последним результатом; `nil` означает «всё получилось».
- `errors.New("текст")` — простейшая ошибка; свой тип с `Error() string` — ошибка с данными внутри.
- `if err != nil { ... }` — главная идиома Go; подробности — в секции «Обработка ошибок».
