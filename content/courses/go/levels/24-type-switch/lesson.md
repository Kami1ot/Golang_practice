# any, type assertion и type switch — когда тип неизвестен

Интерфейсы намеренно прячут конкретный тип: функции `TotalArea` было всё равно, круг перед ней или прямоугольник. Но иногда нужно наоборот — заглянуть внутрь интерфейсного значения и узнать, что же там лежит. Сегодня три инструмента для этого: пустой интерфейс `any` (принимает вообще всё), type assertion (достаёт конкретный тип обратно) и type switch (разбирает варианты веером).

## Пустой интерфейс: контракт без требований

Интерфейс — контракт из методов. А если методов в контракте... ноль?

```go
// Объявлено в самом языке (начиная с Go 1.18):
type any = interface{}
```

`interface{}` — интерфейс без единого требования. Какой тип его реализует? **Любой**: у каждого типа есть как минимум ноль методов. `any` — просто короткий псевдоним для записи `interface{}`, читается приятнее.

```go
var x any

x = 42               // можно
x = "строка"         // можно
x = []int{1, 2, 3}   // тоже можно
x = Circle{R: 1}     // и это
```

Вы давно пользуетесь `any`, сами того не зная. Сигнатура старого знакомого:

```go
func Println(a ...any) (n int, err error)
```

Вот почему `fmt.Println` печатает что угодно и в любом количестве — он принимает variadic-пачку `any`.

## Цена всеядности

Чем меньше интерфейс требует, тем меньше он позволяет. У `Shape` был хотя бы `Area()` — у `any` нет **ничего**:

```go
var x any = 42

fmt.Println(x + 1) // ошибка компиляции: оператор + не определён для any
```

Внутри лежит `int`, мы это видим — но для компилятора `x` имеет тип `any`, а у `any` нет ни методов, ни арифметики. Чтобы работать со значением, надо сначала вернуть ему конкретный тип.

## Type assertion: «а ну-ка, покажи тип»

Утверждение типа (*type assertion*) достаёт конкретное значение из интерфейса:

```go
var x any = "секрет"

s := x.(string)  // s — уже настоящий string
fmt.Println(s + "!") // секрет!
```

Синтаксис `x.(T)` читается: «утверждаю, что внутри x лежит T». Если утверждение верно — получаем значение типа `T`. А если нет?

```go
var x any = "секрет"

n := x.(int) // паника: interface conversion: interface {} is string, not int
```

Программа падает. Поэтому одиночная форма — для случаев, когда вы уверены на сто процентов. Для всего остального есть безопасная форма — старая знакомая ok-идиома, как у карт:

```go
var x any = "секрет"

s, ok := x.(string)
fmt.Println(s, ok) // секрет true

n, ok := x.(int)
fmt.Println(n, ok) // 0 false — паники нет, просто нулевое значение и false
```

> [!WARNING]
> Assertion — это проверка, а НЕ конвертация. Если внутри `any` лежит `int`, то `x.(float64)` вернёт `false` (а одиночная форма — панику), хотя int «легко превратить» в float64. Утверждение сработает только на ТОЧНЫЙ тип. Сначала достаньте `int`, потом конвертируйте: `float64(x.(int))`.

## Type switch: разбор по типам веером

Когда вариантов несколько, цепочка assertion'ов громоздка. Для этого есть специальная форма switch:

```go
func Describe(v any) string {
	switch t := v.(type) {
	case int:
		return fmt.Sprintf("целое число %d", t)
	case string:
		return fmt.Sprintf("строка из %d символов", len([]rune(t)))
	case bool:
		return fmt.Sprintf("булево значение %t", t)
	default:
		return "что-то незнакомое"
	}
}

fmt.Println(Describe(42))      // целое число 42
fmt.Println(Describe("го"))    // строка из 2 символов
fmt.Println(Describe(true))    // булево значение true
fmt.Println(Describe(3.14))    // что-то незнакомое
```

Магия в строчке `switch t := v.(type)`: в каждой ветке переменная `t` имеет **конкретный тип этой ветки**. В `case int` она `int` — можно считать; в `case string` — `string`, работают `len` и срезы. Слово `type` здесь пишется буквально — это специальный синтаксис, который живёт только в switch.

> [!NOTE]
> Ветка с несколькими типами — `case int, float64:` — допустима, но внутри неё `t` остаётся `any`: компилятор же не знает, который из двух. Нужно работать со значением — пишите отдельные ветки. В ветке `default` `t` тоже остаётся `any`.

## Достать конкретный тип из СВОЕГО интерфейса

Assertion работает с любым интерфейсом, не только с `any`. Помните, как `Shape` прятал поля фигур?

```go
var s Shape = Circle{R: 2}

// s.R — ошибка компиляции: у Shape нет поля R
if c, ok := s.(Circle); ok {
	fmt.Println(c.R) // 2 — достали круг, поля снова доступны
}
```

Так решается загадка прошлых уровней: интерфейс сузил обзор — assertion возвращает полный доступ.

## Когда НЕ надо

Инструмент мощный, и новички начинают пихать `any` повсюду. Правило простое:

- **Типы известны заранее?** Объявляйте их явно: `func Sum(nums []int)`, а не `func Sum(nums []any)`. Компилятор поймает ошибки до запуска.
- **Есть общее поведение?** Заведите обычный интерфейс с методом: `TotalArea([]Shape)` не нуждается ни в каких switch.
- **Тип действительно неизвестен до рантайма?** Вот тогда `any` + type switch. Классика: разбор произвольного JSON, функции вроде `fmt.Println`, данные из внешних систем.

В Go `any` — инструмент граничных ситуаций, а не образ жизни. Чем конкретнее типы, тем больше ошибок ловится бесплатно.

## Типичные ошибки новичка

| Код | Что случится | Как чинить |
|---|---|---|
| `n := x.(int)`, а внутри строка | паника: `interface conversion` | ok-форма: `n, ok := x.(int)` |
| `x.(float64)`, а внутри `int` | `false` (или паника): assertion не конвертирует | достать точный тип, потом привести: `float64(x.(int))` |
| `var n int = 5; n.(int)` | ошибка компиляции: assertion работает только на интерфейсах | n уже int — assertion не нужен |
| работать с `t` в ветке `case int, float64:` как с числом | ошибка компиляции: в общей ветке t остаётся any | разнести по отдельным веткам |
| `switch v.(type)` без `default` при неучтённом типе | ни одна ветка не сработает — молчаливый пропуск | добавить `default` с внятной реакцией |
| `func Sum(nums []any)` для суммы чисел | компилятор перестал ловить ошибки типов, всё уехало в рантайм | конкретные типы: `[]int` |

## Запомнить

- `any` = `interface{}` — интерфейс без требований, его реализует любой тип. Именно так работает `fmt.Println(a ...any)`.
- У `any` нет ни методов, ни операторов: чтобы работать со значением, тип нужно вернуть.
- `v := x.(T)` — достать тип: верно — получили `T`, неверно — паника.
- `v, ok := x.(T)` — безопасная ok-форма: вместо паники будет `false`.
- Assertion проверяет ТОЧНЫЙ тип, конвертацией не занимается.
- `switch t := v.(type)` — разбор по типам; в каждой ветке `t` уже конкретного типа (кроме веток-списков и default).
- Assertion работает с любым интерфейсом: `s.(Circle)` возвращает доступ к полям, которые прятал `Shape`.
- `any` — для действительно неизвестных типов; известны заранее — объявляйте конкретно.
