# Структуры (struct) — свои составные типы

До сих пор все данные жили в переменных «по одной»: имя отдельно, возраст отдельно. Пока данных мало — терпимо. Но настоящие программы описывают *вещи*: игрока, товар, точку на карте. У вещи несколько свойств, и таскать их россыпью — верный путь к путанице. Структура (*struct*) собирает связанные данные под одним именем — и это первый шаг к проектированию собственных типов.

## Зачем структуры

Храним данные о человеке без структур:

```go
name := "Аня"
age := 20
city := "Казань"
```

Для одного человека — три переменные. Для двоих — шесть. Для списка людей придётся заводить **параллельные слайсы**:

```go
names := []string{"Аня", "Боря"}
ages := []int{20, 25}
cities := []string{"Казань", "Минск"}
```

Это работает, но хрупко: удалили элемент из `names` и забыли про `ages` — и теперь возрасты «съехали» к чужим именам. Никакой компилятор такое не поймает.

Структура решает проблему радикально: человек становится **одним значением**, которое передаётся, копируется и кладётся в слайс целиком — поля не разбегаются.

## Объявляем свой тип

```go
type Person struct {
    Name string
    Age  int
}
```

Разбор по словам:

- `type` — ключевое слово: «объявляю новый тип»;
- `Person` — имя типа (придумываете сами);
- `struct { … }` — из чего тип состоит: список **полей** (*fields*), у каждого имя и тип.

Поля одного типа можно перечислить через запятую в одной строке:

```go
type Point struct {
    X, Y int
}
```

Объявление типа кладут на уровне файла — вне `func main`, рядом с другими функциями, — чтобы тип был виден всем функциям программы.

## Создаём значения

### Нулевое значение

Структуру можно объявить через `var` — и это не ошибка, а готовое к работе значение, где **каждое поле равно своему нулю**: строки — `""`, числа — `0`.

```go
var p Person
fmt.Println(p.Age)        // 0
fmt.Println(p.Name == "") // true
```

### Литерал с именами полей — рекомендуемый

```go
p := Person{Name: "Аня", Age: 20}
fmt.Println(p) // {Аня 20}
```

Пишете `Поле: значение` через запятую. Два бонуса: порядок полей не важен, и можно указать только часть — остальные получат нулевые значения:

```go
q := Person{Name: "Боря"} // Age автоматически 0
```

### Позиционный литерал — хрупкий

```go
p := Person{"Аня", 20}
```

Короче, но значения обязаны идти **строго в порядке объявления полей**, и указать нужно **все** поля сразу. Чем это опасно: добавите в `Person` новое поле или поменяете поля местами — все позиционные литералы в программе либо перестанут компилироваться, либо (хуже) тихо перепутают смысл значений.

| | С именами `Person{Name: "Аня", Age: 20}` | Позиционный `Person{"Аня", 20}` |
|---|---|---|
| Порядок значений | любой | строго как в объявлении типа |
| Часть полей | можно, остальные — нулевые | нельзя, только все сразу |
| В тип добавили поле | код работает как работал | ломается или путает значения |
| Читаемость | видно, что чему присвоено | нужно помнить объявление типа |

> [!NOTE]
> Правило хорошего тона: по умолчанию — литерал с именами. Позиционный допустим для крошечных очевидных типов вроде `Point{1, 2}`.

## Точка: доступ и присваивание

К полю обращаются через точку — читают и присваивают как обычную переменную:

```go
p := Person{Name: "Аня", Age: 20}
fmt.Println(p.Name) // Аня

p.Age = 21
p.Age++             // всё, что можно с переменной, можно и с полем
fmt.Println(p.Age)  // 22
```

Имена полей чувствительны к регистру: поле называется `Age` — значит `p.age` не скомпилируется.

## Структура — это значение: всё копируется

Присваивание структуры делает **полную копию** всех полей. Дальше копия и оригинал живут независимо:

```go
a := Point{X: 1, Y: 2}
b := a        // копия!
b.X = 100
fmt.Println(a.X, b.X) // 1 100 — оригинал не пострадал
```

Передача в функцию — то же самое присваивание, параметр получает копию:

```go
func birthday(p Person) {
    p.Age++ // подросла только копия
}

func main() {
    p := Person{Name: "Аня", Age: 20}
    birthday(p)
    fmt.Println(p.Age) // 20 — оригинал как был
}
```

> [!WARNING]
> Функция, меняющая параметр-структуру, меняет **свою копию** — снаружи изменений не видно. Это самая частая неожиданность уровня. Способ дать функции доступ к оригиналу — указатели (*pointers*), им посвящён следующий уровень. Пока пользуйтесь честным приёмом: функция возвращает изменённую копию.

## Функции и структуры

Структуры принимают и возвращают как значения любого другого типа:

```go
func older(a, b Person) Person {
    if a.Age >= b.Age {
        return a
    }
    return b
}
```

А вот приём «верни изменённую копию» в деле:

```go
func renamed(p Person, name string) Person {
    p.Name = name // правим свою копию…
    return p      // …и отдаём её наружу
}

p = renamed(p, "Анна") // вызывающий сам перезаписывает переменную
```

## Вложенные структуры

Поле структуры может быть структурой другого типа:

```go
type Address struct {
    City   string
    Street string
}

type User struct {
    Name string
    Addr Address // поле-структура
}
```

Литерал вкладывается в литерал, а к глубоким полям ведёт цепочка точек:

```go
u := User{
    Name: "Аня",
    Addr: Address{City: "Казань", Street: "Кремлёвская"},
}
fmt.Println(u.Addr.City) // Казань
u.Addr.Street = "Баумана" // присваивание по цепочке тоже работает
```

## Сравнение структур

Если все поля сравнимы (числа, строки, bool, такие же структуры), то структуры можно сравнивать оператором `==` — он сверяет поля попарно:

```go
a := Point{1, 2}
b := Point{X: 1, Y: 2}
fmt.Println(a == b)           // true — все поля совпали
fmt.Println(a == Point{2, 1}) // false
```

А вот структуру с полем-слайсом или полем-картой сравнить через `==` нельзя — это ошибка компиляции: сравнивайте нужные поля по отдельности.

## Слайс структур

Самое частое место жительства структур — слайс. В литерале слайса имя типа у каждого элемента можно опускать:

```go
people := []Person{
    {Name: "Аня", Age: 20},  // Person{...} писать не обязательно
    {Name: "Боря", Age: 25},
}

for _, p := range people {
    fmt.Println(p.Name, p.Age)
}
// Аня 20
// Боря 25
```

> [!WARNING]
> range-переменная — тоже **копия** элемента! Менять её бесполезно: слайс не изменится. Настоящее изменение — только по индексу.

```go
for _, p := range people {
    p.Age++ // изменилась копия — слайс не тронут
}
fmt.Println(people[0].Age) // 20

for i := range people {
    people[i].Age++ // а вот так — по-настоящему
}
fmt.Println(people[0].Age) // 21
```

Поиск «лучшего» элемента — классика, которая понадобится в задачах. Копирование здесь не мешает, а помогает: в переменной `best` лежит копия текущего лидера.

```go
type Book struct {
    Title string
    Pages int
}

books := []Book{
    {Title: "Go 101", Pages: 320},
    {Title: "Задачник", Pages: 480},
    {Title: "Брошюра", Pages: 24},
}

thickest := books[0]
for _, b := range books[1:] {
    if b.Pages > thickest.Pages {
        thickest = b
    }
}
fmt.Println(thickest.Title) // Задачник
```

## Структуры как значения карты

Карта может хранить структуры: `map[string]Point`. Но есть засада:

```go
m := map[string]Point{
    "старт": {X: 0, Y: 0},
}
m["старт"].X = 5 // ОШИБКА КОМПИЛЯЦИИ: cannot assign to struct field
```

Чтение `m["старт"]` возвращает **копию** значения, и присваивать полю копии-однодневки Go запрещает — изменение всё равно бы потерялось.

> [!NOTE]
> Рецепт для карт: достань копию → измени → положи обратно.
>
> ```go
> p := m["старт"]
> p.X = 5
> m["старт"] = p
> ```

## Типичные ошибки новичка

| Код | Что случится | Как чинить |
|---|---|---|
| `Person{"Аня"}` | ошибка компиляции: указаны не все поля | позиционному литералу нужны ВСЕ поля; лучше — с именами |
| `p.age` при поле `Age` | ошибка компиляции: такого поля нет | имена полей чувствительны к регистру: `p.Age` |
| функция меняет параметр-структуру | оригинал не изменился — правилась копия | вернуть изменённую копию (или указатели — след. уровень) |
| `for _, p := range people { p.Age++ }` | слайс остался прежним | менять по индексу: `people[i].Age++` |
| `m[k].X = 5` для карты структур | ошибка компиляции: cannot assign | копия → правка → обратно: `v := m[k]; v.X = 5; m[k] = v` |
| `==` для структур со слайсом внутри | ошибка компиляции: тип несравним | сравнивать нужные поля по отдельности |

## Запомнить

- `type Имя struct { Поле Тип; … }` — свой составной тип; объявляется вне функций.
- `var p Person` — все поля нулевые; литерал с именами `Person{Name: "Аня", Age: 20}` — рекомендуемый способ создания; позиционный — хрупкий.
- Доступ и присваивание — через точку: `p.Age = 21`; вложенные — цепочкой `u.Addr.City`.
- Структура — **значение**: присваивание, передача в функцию, range-переменная — всегда копия.
- Функции спокойно принимают и возвращают структуры; «изменить» структуру в функции = вернуть изменённую копию.
- Элементы слайса структур меняют по индексу: `people[i].Age++`.
- `m[k].X = 5` не скомпилируется: достаньте копию, поправьте, положите обратно.
- `==` сравнивает структуры по полям — если все поля сравнимы.
