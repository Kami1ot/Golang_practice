# Указатели — как изменить чужую переменную

На прошлом уровне вы упёрлись в стену: передаёшь структуру в функцию — а функция получает **копию** и честно правит её, не трогая оригинал. Сегодня стена рушится. Указатель (*pointer*) — это способ дать функции не копию значения, а **адрес**, по которому лежит оригинал.

## Проблема: функция получает копию

Знакомая с 16 уровня ситуация, только на числе:

```go
func tryDouble(n int) {
	n = n * 2 // удвоили... локальную копию
}

func main() {
	x := 10
	tryDouble(x)
	fmt.Println(x) // 10 — оригинал даже не заметил
}
```

`tryDouble` не сломана — она сделала ровно то, что умеет Go: скопировала аргумент, удвоила копию, а копия исчезла вместе с завершением функции. Так ведут себя и числа, и строки, и структуры. Чтобы функция изменила **сам** `x`, ей нужно знать, **где он живёт**.

## Указатель = адрес значения

Каждая переменная живёт в памяти по какому-то адресу — как квартира в доме. Указатель — это переменная, в которой лежит такой адрес. Оператор `&` («амперсанд») берёт адрес:

```go
x := 42
p := &x        // p хранит адрес переменной x
fmt.Println(p) // что-то вроде 0xc000012028 — адрес (у вас будет другой)
```

Тип у `p` — `*int`, читается «указатель на int». Для любого типа `T` существует тип `*T`: `*string`, `*float64`, `*Point`. Полная форма объявления выглядит так:

```go
var age int = 30
var pAge *int = &age // указатель на int, указывает на age
```

## Разыменование: сходить по адресу

Оператор `*` перед указателем — разыменование (*dereference*): «сходи по адресу и работай с тем, что там лежит». Работает в обе стороны — и на чтение, и на запись:

```go
x := 42
p := &x
fmt.Println(*p) // 42 — прочитали значение по адресу
*p = 100        // записали новое значение по адресу
fmt.Println(x)  // 100 — изменился сам x!
```

Мнемоника: `&` спрашивает «где живёшь?», `*` говорит «схожу-ка по адресу».

> [!NOTE]
> Символ `*` играет две роли: в **типе** (`*int` — «указатель на int») и как **оператор** (`*p` — «значение по адресу p»). Это одна и та же звёздочка в разных позициях — быстро привыкаешь.

## Функция, которая меняет оригинал

Соединяем: параметр-указатель + разыменование внутри = функция-модификатор:

```go
func double(n *int) {
	*n = *n * 2 // пишем по адресу — меняется оригинал
}

func main() {
	x := 10
	double(&x)     // отдаём не значение, а адрес
	fmt.Println(x) // 20
}
```

По шагам: `&x` — адрес `x` уезжает в функцию; внутри `*n` читает 10, умножает, `*n =` записывает 20 **по тому же адресу**. Функция закончилась, а изменение осталось — оно было сделано прямо в `x`.

Классика жанра — обмен двух переменных местами:

```go
func swap(a, b *int) {
	*a, *b = *b, *a
}

func main() {
	x, y := 1, 2
	swap(&x, &y)
	fmt.Println(x, y) // 2 1
}
```

## Так вот что значил fmt.Scan(&x)!

С самого первого уровня вы писали:

```go
var n int
fmt.Scan(&n)
```

Секрет раскрыт: `Scan` получает **адрес** переменной и записывает прочитанное по этому адресу — ровно как наша `double`. Получи он `n` по значению — заполнил бы копию, а ваша переменная так и осталась бы нулём. Забудете `&` — компилятор промолчит, но `Scan` вернёт ошибку и ничего не прочитает.

## Копия указателя — не копия значения

Присваивание копирует сам указатель, то есть адрес. Оба указателя после этого смотрят на одну и ту же переменную:

```go
x := 1
a := &x
b := a             // скопировали адрес, не значение
*b = 5
fmt.Println(x, *a) // 5 5 — x, *a и *b — одна и та же ячейка
```

## nil — указатель в никуда

Нулевое значение (*zero value*) указателя — `nil`: «не указывает никуда». Указатели можно сравнивать через `==` и `!=`:

```go
var p *int            // адреса не давали
fmt.Println(p == nil) // true
```

> [!WARNING]
> Разыменовать `nil` — значит сходить по несуществующему адресу. Программа рухнет с паникой:
>
> ```go
> var p *int
> fmt.Println(*p) // ПАНИКА!
> ```
>
> ```
> panic: runtime error: invalid memory address or nil pointer dereference
> ```
>
> Увидели такой текст — где-то разыменовался нулевой указатель. Если указатель мог не получить адреса, сначала проверьте: `if p != nil { ... }`.

## Указатель на структуру

Главный практический случай — структуры. Функция по указателю правит оригинал, а не копию:

```go
type Person struct {
	Name string
	Age  int
}

func birthday(p *Person) {
	p.Age++ // с днём рождения настоящую Алису, не копию
}

func main() {
	alice := Person{Name: "Алиса", Age: 29}
	birthday(&alice)
	fmt.Println(alice.Age) // 30
}
```

> [!NOTE]
> По строгим правилам разыменования следовало бы писать `(*p).Age++`. Go разрешает сокращение: у указателя на структуру к полям обращаются просто через точку — `p.Age` — компилятор разыменует сам. Пишите как с обычной структурой, скобки не нужны.

## Когда указатели нужны, а когда нет

Нужны:

- функция должна **изменить** переданное значение — `double`, `Scan`, «сдвинь точку», «пополни счёт»;
- структура большая, и копировать её при каждом вызове жалко — передают адрес.

Не нужны:

- функция только **читает** значение — передавайте по значению, копия даже безопаснее: функция физически не может испортить оригинал.

> [!NOTE]
> Слайсам и картам указатели почти никогда не нужны: они «ссылочные» сами по себе — функция, получившая слайс или карту, меняет те же самые элементы (вы видели это на уровнях 7–8). Как это устроено внутри — отдельная история; пока правило простое: `*int`, `*Person` — да, `*[]int` и указатель на карту — почти никогда.
>
> Ещё вам может встретиться `p := new(int)` — создать безымянную переменную и сразу получить её адрес. Пока хватает `&x`.

## Значение vs указатель

| | `int` (значение) | `*int` (указатель) |
|---|---|---|
| Что хранит | само число | адрес числа |
| Нулевое значение | `0` | `nil` |
| В функцию попадает | копия | адрес оригинала |
| Функция может изменить оригинал? | нет | да |
| Прочитать | `x` | `*p` |
| Записать | `x = 5` | `*p = 5` |

Мини-шпаргалка по синтаксису:

| Запись | Смысл |
|---|---|
| `&x` | взять адрес переменной `x` |
| `*int` | тип «указатель на int» |
| `*p` | значение по адресу `p` (разыменование) |
| `p.Field` | поле структуры по указателю (Go разыменует сам) |
| `p == nil` | указатель никуда не указывает? |

А вот **арифметики указателей в Go нет**: `p + 1`, как в C, не скомпилируется — указатель нельзя «сдвинуть на соседнюю ячейку», и это закрывает целый класс болезненных ошибок.

## Типичные ошибки новичка

| Код | Что случится | Как чинить |
|---|---|---|
| `var p *int; *p = 5` | паника: nil pointer dereference | сначала дать адрес: `p = &x` |
| `double(x)` вместо `double(&x)` | ошибка компиляции: `cannot use x (variable of type int) as *int value` | передавать адрес: `double(&x)` |
| `n = n * 2` внутри `func double(n *int)` | ошибка компиляции: `mismatched types *int and untyped int` | разыменовать: `*n = *n * 2` |
| `fmt.Scan(n)` без `&` | компилируется, но переменная останется нулевой (Scan вернёт ошибку) | `fmt.Scan(&n)` |
| `(*p).Name` у указателя на структуру | работает, но загромождает код | достаточно `p.Name` |

## Запомнить

- Аргументы в Go **копируются**; указатель — легальный способ дать функции доступ к оригиналу.
- `&x` — взять адрес (получится тип `*int`); `*p` — прочитать или записать значение по адресу.
- `func f(n *int)` меняет оригинал; вызывается как `f(&x)`.
- `fmt.Scan(&x)` — тот самый приём: Scan пишет прочитанное по адресу вашей переменной.
- Нулевое значение указателя — `nil`; разыменование `nil` = паника. Страховка: `if p != nil`.
- У указателя на структуру поля доступны напрямую: `p.Name`, без `(*p).Name`.
- Слайсы и карты передаются без указателей — они «ссылочные» сами по себе.
- Арифметики указателей в Go нет — и хорошо.
