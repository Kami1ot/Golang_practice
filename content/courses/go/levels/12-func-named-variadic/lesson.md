# Именованные результаты и variadic — функции с удобствами

На прошлом уровне вы научились объявлять функции, принимать параметры и возвращать несколько значений. Сегодня — два удобства, которые делают функции выразительнее: результаты с именами, которые читаются как документация, и функции, принимающие сколько угодно аргументов. Вторыми вы, между прочим, пользуетесь с самого первого уровня — просто ещё не знали об этом.

## Именованные возвращаемые значения

Результатам функции можно дать имена — прямо в сигнатуре:

```go
func divmod(a, b int) (div, mod int) {
    div = a / b
    mod = a % b
    return div, mod
}

func main() {
    d, m := divmod(17, 5)
    fmt.Println(d, m)       // 3 2
}
```

Такая запись — именованные возвращаемые значения (*named return values*). Сигнатура теперь сама рассказывает, ЧТО возвращает функция. Сравните:

```go
func divmod(a, b int) (int, int)         // какое из двух — остаток?..
func divmod(a, b int) (div, mod int)     // ага: сначала частное, потом остаток
```

Два правила, которые стоит выучить сразу:

1. Именованные результаты — это **готовые переменные**: внутри функции они уже объявлены, присваивайте им значения без `:=`.
2. На старте они равны **нулевым значениям** (*zero values*) своих типов: `0` для чисел, `""` для строк, `false` для `bool` — ровно как при объявлении через `var`.

```go
func nothing() (n int, s string) {
    return n, s             // никто ничего не присваивал
}

func main() {
    num, str := nothing()
    fmt.Println(num, str == "")     // 0 true
}
```

## «Голый» return

Раз результаты уже названы, Go разрешает написать `return` вообще без значений — вернутся текущие значения именованных результатов. Это называется голый return (*naked return*):

```go
func divmod(a, b int) (div, mod int) {
    div = a / b
    mod = a % b
    return                  // вернёт div и mod — то, что в них лежит сейчас
}
```

> [!WARNING]
> Голый return хорош в коротких функциях, которые видно целиком. В длинной функции читателю придётся прокручивать код вверх и вычислять в уме, что сейчас лежит в результатах. Правило хорошего тона: функция не помещается на экран — пишите `return` с явными значениями. Компилятору всё равно, людям — нет.

И ещё: голый `return` работает ТОЛЬКО с именованными результатами. Если результаты безымянные, `return` без значений — ошибка компиляции: `not enough return values`.

## Функция, которая ест сколько угодно аргументов

Теперь второй герой уровня. Три точки перед типом параметра — `...int` — превращают его в вариативный (*variadic*): функция принимает **любое** число аргументов этого типа.

```go
func Sum(nums ...int) int {
    total := 0
    for _, v := range nums {
        total += v
    }
    return total
}

func main() {
    fmt.Println(Sum(1, 2))          // 3
    fmt.Println(Sum(1, 2, 3, 4))    // 10
    fmt.Println(Sum(7))             // 7
    fmt.Println(Sum())              // 0 — и так можно!
}
```

Главный секрет: **внутри функции `nums` — самый обычный слайс** `[]int`. Никакой магии: `len`, `range`, индексы — всё работает как с любым слайсом из седьмого уровня.

```go
func describe(nums ...int) {
    fmt.Println("аргументов:", len(nums))
}

func main() {
    describe(10, 20, 30)    // аргументов: 3
    describe()              // аргументов: 0
}
```

> [!NOTE]
> Вызов вообще без аргументов — законная, штатная ситуация: внутри окажется пустой слайс, `len(nums) == 0`, а `range` по нему просто не выполнится ни разу. Если пустой вызов требует особого ответа — проверьте `len(nums) == 0` в начале функции.

## Вы уже давно пользуетесь variadic

`fmt.Println` спокойно принимает и ноль, и один, и десять аргументов — теперь понятно почему: это вариативная функция. И `append(s, 1, 2, 3)`, дописывающая к слайсу сколько угодно элементов, — тоже она. Вариативность — не экзотика, а повседневный инструмент стандартной библиотеки.

## Распаковка слайса: nums...

А если числа уже лежат в слайсе? Передать его «как есть» нельзя — `Sum(data)` не скомпилируется: функция ждёт `int`-ы, а получает `[]int`. Нужна распаковка (*slice unpacking*) — три точки ПОСЛЕ имени слайса:

```go
data := []int{3, 5, 7}
fmt.Println(Sum(data...))   // 15 — как будто написали Sum(3, 5, 7)
```

Заметьте зеркальность: в объявлении точки стоят *перед типом* (`...int`), а в вызове — *после слайса* (`data...`). Это не строка и не отдельный оператор — просто суффикс аргумента в вызове.

## Обычные параметры + variadic

Вариативный параметр можно сочетать с обычными, но он обязан быть **последним** в списке:

```go
func announce(prefix string, events ...string) {
    for _, e := range events {
        fmt.Println(prefix, e)
    }
}

func main() {
    announce(">>", "старт", "финиш")
    // >> старт
    // >> финиш
}
```

Компилятор раздаёт аргументы просто: первый уходит в `prefix`, всё остальное — в `events`. Написать `func bad(nums ...int, name string)` нельзя — ошибка компиляции: после вариативного параметра ничего стоять не может, иначе непонятно, где заканчиваются `nums`.

## Пример побольше: максимум

Соберём всё изученное в одну функцию: именованный результат, variadic и обработка пустого вызова.

```go
func Max(nums ...int) (max int) {
    if len(nums) == 0 {
        return              // max уже 0 — нулевое значение
    }
    max = nums[0]           // стартуем с ПЕРВОГО элемента, не с нуля!
    for _, v := range nums {
        if v > max {
            max = v
        }
    }
    return max
}

func main() {
    fmt.Println(Max(3, 1, 4))       // 4
    fmt.Println(Max(-5, -2, -9))    // -2
    fmt.Println(Max())              // 0
}
```

> [!WARNING]
> Стартовать поиск максимума (или минимума) с нуля — классическая ловушка: на наборе из одних отрицательных чисел (`Max(-5, -2, -9)`) ноль «победит» все элементы, и ответ окажется неверным. Точка отсчёта — первый элемент набора.

## Шпаргалка: где какие точки

| Где | Как пишется | Что значит |
|---|---|---|
| Объявление параметра | `nums ...int` | функция примет любое число `int` |
| Внутри функции | `nums` | обычный слайс `[]int` |
| Вызов с готовым слайсом | `Sum(data...)` | распаковать слайс в аргументы |

## Типичные ошибки новичка

| Код | Что случится | Как чинить |
|---|---|---|
| `func f(nums ...int, s string)` | ошибка компиляции | variadic-параметр — только последний |
| `Sum(data)` для `data []int` | `cannot use data ... as int value` | добавить распаковку: `Sum(data...)` |
| `Sum(1, data...)` | ошибка компиляции: `too many arguments` | распаковка не смешивается с перечислением — либо всё перечислить, либо собрать один слайс |
| `Sum("data...")` | точки оказались внутри строки | `...` — не текст, а суффикс имени слайса: `Sum(data...)` |
| голый `return` в функции на 50 строк | компилируется, но читается мучительно | в длинных функциях — `return` с явными значениями |
| `min := 0` перед поиском минимума | на положительных числах ответ всегда 0 | стартовать с первого элемента набора |

## Запомнить

- `(div, mod int)` — именованные результаты: читаются как документация и на старте равны нулевым значениям своих типов.
- Голый `return` возвращает текущие значения именованных результатов. В длинных функциях пишите явный `return` — берегите читателя.
- `nums ...int` — вариативный параметр; внутри функции это обычный слайс `[]int` со всеми привычными операциями.
- Вызывать variadic-функцию можно с любым числом аргументов, включая ноль: пустой вызов — штатная ситуация, `len(nums) == 0`.
- Готовый слайс передаётся с распаковкой: `Sum(data...)`. Точки в объявлении — перед типом, в вызове — после слайса.
- Вариативный параметр — всегда последний в списке; `fmt.Println` и `append` — давно знакомые вам variadic-функции.
