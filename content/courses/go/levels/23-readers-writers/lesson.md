# io.Reader и io.Writer — универсальные потоки байтов

Файл, сетевое соединение, терминал, строка в памяти — на первый взгляд ничего общего. Но из каждого можно **читать** байты, и почти в каждый можно их **писать**. Пакет `io` свёл это к двум крошечным интерфейсам — `Reader` и `Writer`, — и половина стандартной библиотеки разговаривает именно на их языке. Сегодня вы поймёте, что пользовались ими с первого уровня, не подозревая об этом.

## Проблема: куда писать — решают за нас

Представьте функцию, которая печатает отчёт. Сегодня отчёт нужен в терминале. Завтра — в файле. В тестах — в строке, чтобы сверить содержимое. Писать три версии одной функции? У Go ответ другой: функция пишет «куда скажут» — в любое место, куда можно записать байты.

## io.Writer: «сюда можно писать»

```go
// Объявлен в пакете io:
type Writer interface {
	Write(p []byte) (n int, err error)
}
```

Один метод: принял срез байтов — записал — вернул, сколько записал, и ошибку (или `nil`). Всё, что умеет так делать, — уже `io.Writer`: терминал `os.Stdout`, открытый файл, сетевое соединение, буфер в памяти.

Знакомьтесь с семейством функций `Fprint` из пакета `fmt` — та же печать, но первым аргументом принимает **куда**:

```go
fmt.Fprintf(os.Stdout, "привет, %s!\n", "мир") // привет, мир!
fmt.Fprintln(os.Stdout, "и ещё строка")        // и ещё строка
```

Маленькое открытие: `fmt.Println(...)` — это просто сокращение для `fmt.Fprintln(os.Stdout, ...)`. Вы отправляли байты в `io.Writer` с самого первого «Привет, Go!».

## bytes.Buffer — писатель в память

Для задач и тестов важнее всего третий писатель — буфер (*buffer*) из пакета `bytes`. Это «блокнот в памяти»: копит всё, что в него записали, и по запросу отдаёт строкой:

```go
var buf bytes.Buffer

fmt.Fprintf(&buf, "%d + %d = %d\n", 2, 3, 2+3)
buf.WriteString("готово")

fmt.Println(buf.String())
// 2 + 3 = 5
// готово
```

Нулевое значение буфера сразу готово к работе — `var buf bytes.Buffer`, и пишите.

> [!WARNING]
> В `Fprintf` передаётся именно `&buf`, с адресом. Метод `Write` у буфера объявлен с получателем-указателем (он ведь меняет содержимое!) — а вы помните правило с уровня про интерфейсы: указательные методы входят в набор только `*T`. Передадите `buf` без амперсанда — компилятор ответит `does not implement io.Writer`.

## Функция, принимающая io.Writer

Теперь соберём идиому целиком — функция пишет «куда скажут»:

```go
func WriteGreeting(w io.Writer, name string) {
	fmt.Fprintf(w, "Привет, %s!", name)
}

WriteGreeting(os.Stdout, "Гоша") // Привет, Гоша! — в терминал

var buf bytes.Buffer
WriteGreeting(&buf, "тест")      // то же самое — в память
fmt.Println(buf.String())        // Привет, тест!
```

Одна функция — и терминал, и файл, и буфер. Именно так стандартная библиотека тестирует вывод: подсунул буфер, сверил строку. В задачах уровня будете делать то же самое.

## io.Reader: «отсюда можно читать»

Зеркальный близнец:

```go
// Объявлен в пакете io:
type Reader interface {
	Read(p []byte) (n int, err error)
}
```

Читатели: `os.Stdin`, открытый файл, тело HTTP-ответа, строка, завёрнутая в `strings.NewReader`.

Метод `Read` — низкоуровневый: он заполняет переданный буфер порциями, и вызывать его напрямую хлопотно. В повседневном коде берут помощников. Главный — `io.ReadAll`: выпивает читателя до дна и отдаёт все байты:

```go
r := strings.NewReader("тише едешь — дальше будешь")

data, err := io.ReadAll(r) // data — []byte
if err != nil {
	fmt.Println("не дочитали:", err)
	return
}
fmt.Println(string(data)) // тише едешь — дальше будешь
```

`string(data)` — знакомая с уровня про строки конверсия байтов в строку. И обратите внимание на проверку `err` — прошлый уровень в действии: чтение может сорваться (файл исчез, сеть оборвалась), и `ReadAll` честно сообщит об этом ошибкой.

> [!NOTE]
> Как читатель сообщает «я всё»? Метод `Read` возвращает особую ошибку `io.EOF` (*end of file* — конец потока). Помощники вроде `ReadAll` обрабатывают её сами, поэтому в обычном коде вы `io.EOF` почти не встретите — но знать, что поток заканчивается именно так, полезно.

## io.Copy: соединить читателя с писателем

Раз есть «откуда» и «куда», должна быть труба между ними:

```go
r := strings.NewReader("привет, поток!\n")

n, err := io.Copy(os.Stdout, r) // печатает: привет, поток!
fmt.Println(n, err)             // 26 <nil>
```

`io.Copy(dst, src)` перекачивает всё из читателя в писателя и возвращает число скопированных **байтов**: в нашей строке их 26, хотя символов — 15 (кириллица занимает по два байта — привет от уровня про руны). Порядок аргументов — как у присваивания: сначала куда, потом откуда.

## Свой Writer — это просто

Контракт из одного метода — значит, свой писатель пишется за минуту. Например, счётчик байтов:

```go
type CountWriter struct {
	Total int
}

func (w *CountWriter) Write(p []byte) (int, error) {
	w.Total += len(p)
	return len(p), nil
}

cw := &CountWriter{}
fmt.Fprint(cw, "go-go-go")
fmt.Println(cw.Total) // 8
```

Правила контракта: вернуть, сколько байтов из `p` записано (мы «записали» все — `len(p)`), и `nil`, если всё хорошо. Получатель указательный — метод меняет счётчик, — поэтому в `Fprint` уезжает `cw`, который уже адрес (`&CountWriter{}`).

Теперь `CountWriter` можно подсунуть куда угодно, где ждут `io.Writer`, — хоть в `io.Copy`, хоть в `WriteGreeting`. Неявная реализация: пакет `io` о вашем типе не знает — и ему не нужно.

## Кто есть кто в стандартной библиотеке

| Тип | Reader | Writer | Зачем |
|---|---|---|---|
| `os.Stdin` | ✓ | — | клавиатура |
| `os.Stdout` | — | ✓ | терминал |
| `*os.File` | ✓ | ✓ | файлы (секция «Стандартная библиотека») |
| `*bytes.Buffer` | ✓ | ✓ | накопитель в памяти, любимец тестов |
| `*strings.Reader` | ✓ | — | строка как источник |

## Типичные ошибки новичка

| Код | Что случится | Как чинить |
|---|---|---|
| `fmt.Fprintf(buf, ...)` для `var buf bytes.Buffer` | ошибка компиляции: `does not implement io.Writer` — `Write` объявлен у `*bytes.Buffer` | передавать адрес: `&buf` |
| `data, _ := io.ReadAll(r)` | ошибка чтения потеряна: при обрыве получите пустые данные молча | проверять: `if err != nil { return err }` |
| считать символы через `len(p)` в `Write` | `len` считает байты: «привет» — это 12 байт, а не 6 символов | для символов — `len([]rune(string(p)))` |
| вызывать `r.Read(buf)` напрямую и ждать всё сразу | `Read` вправе отдать данные порциями — прочитается кусок | пользоваться `io.ReadAll` / `io.Copy` |
| `io.Copy(src, dst)` — перепутан порядок | данные потекут в обратную сторону (или ошибка компиляции, если src только Reader) | порядок как у присваивания: `Copy(куда, откуда)` |

## Запомнить

- `io.Writer` — один метод `Write([]byte) (int, error)`: «сюда можно писать». `io.Reader` — зеркальный `Read`: «отсюда можно читать».
- `fmt.Fprintf(w, ...)` / `fmt.Fprintln(w, ...)` печатают в ЛЮБОЙ Writer; `fmt.Println` — это `Fprintln` в `os.Stdout`.
- `bytes.Buffer` — писатель и читатель в памяти: `var buf bytes.Buffer`, писать в `&buf`, забирать `buf.String()`.
- Функция с параметром `io.Writer` не знает и не хочет знать, куда пишет, — это делает её универсальной и тестируемой.
- `io.ReadAll(r)` читает поток до конца и возвращает `[]byte`; ошибку — проверять.
- `io.Copy(dst, src)` перекачивает из читателя в писателя; считает байты, не символы.
- Свой Writer — любой тип с методом `Write`; соблюдайте контракт: верните, сколько записали, и `nil` при успехе.
