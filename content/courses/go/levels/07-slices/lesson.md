# Слайсы — рабочая лошадка Go

До сих пор каждая переменная хранила одно значение. Но данные ходят толпами: список оценок, очередь заказов, история ходов. Для «многих значений одного типа» в Go есть массивы (*array*) и слайсы (*slice*). Спойлер: массивы вы будете видеть редко, слайсы — каждый день.

## Массив — жёсткая коробка

Массив хранит **фиксированное** число элементов; длина — часть типа:

```go
var a [3]int          // три нуля: [0 0 0]
a[0] = 10             // индексация с нуля
a[2] = 30
fmt.Println(a)        // [10 0 30]
fmt.Println(len(a))   // 3
```

`[3]int` и `[4]int` — разные, несовместимые типы. Добавить четвёртый элемент в `[3]int` нельзя вообще. Из-за этой жёсткости массивы в Go — редкие гости; они нужны, когда размер известен раз и навсегда. Для всего остального есть слайсы.

## Слайс — гибкое окно

Слайс выглядит как массив без размера в типе — и умеет расти:

```go
nums := []int{3, 1, 4}       // литерал слайса (*slice literal*)
fmt.Println(nums)            // [3 1 4]
fmt.Println(nums[0])         // 3
fmt.Println(len(nums))       // 3

nums[1] = 100                // элементы можно менять
fmt.Println(nums)            // [3 100 4]
```

Индексы — от `0` до `len(s)-1`. Выход за границы компилятор не всегда поймает, зато поймает программа — паникой (*panic*):

```go
fmt.Println(nums[3])
// panic: runtime error: index out of range [3] with length 3
```

Это не ошибка компиляции — программа падает уже на бегу. Проверяйте индексы!

## Три способа создать слайс

```go
s1 := []int{1, 2, 3}         // литерал: сразу с данными
s2 := make([]int, 5)         // make: 5 элементов, заполнены нулями [0 0 0 0 0]
var s3 []int                 // nil-слайс: пустой, длина 0
fmt.Println(s3, len(s3))     // [] 0
```

`var s []int` создаёт nil-слайс — у него нет памяти под элементы, но `len`, `range` и `append` работают с ним без паники. Это удобно: объявили — и сразу пользуемся.

## append — добавить в конец

Слайс растёт функцией `append`:

```go
var s []int
s = append(s, 10)        // [10]
s = append(s, 20, 30)    // [10 20 30] — можно несколько сразу
fmt.Println(s)
```

> [!WARNING]
> Результат `append` нужно **присвоить обратно**: `s = append(s, x)`. Просто `append(s, x)` — ошибка компиляции `append(s, x) (value of type []int) is not used`. Так Go защищает вас: `append` может вернуть НОВЫЙ слайс, и без присваивания добавленный элемент потеряется.

Идиома «прочитать n чисел в слайс»:

```go
var n int
fmt.Scan(&n)

var nums []int
for range n {
    var x int
    fmt.Scan(&x)
    nums = append(nums, x)
}
fmt.Println(nums) // ввод: 3, затем 5 8 13 → [5 8 13]
```

Можно склеить два слайса — многоточие «распаковывает» второй:

```go
a := []int{1, 2}
b := []int{3, 4}
a = append(a, b...)      // [1 2 3 4]
```

## len и cap: длина и вместимость

У слайса два размера:

- `len(s)` — длина (*length*): сколько элементов лежит сейчас;
- `cap(s)` — вместимость (*capacity*): сколько влезет без переезда в новую память.

```go
s := make([]int, 2, 5)   // длина 2, вместимость 5
fmt.Println(len(s), cap(s)) // 2 5

s = append(s, 7)
fmt.Println(len(s), cap(s)) // 3 5 — место ещё было
```

Когда место кончается, `append` выделяет новый массив побольше (обычно примерно вдвое) и переносит туда данные — вы этого не замечаете, всё происходит автоматически. Поэтому `append` дёшев, и им пользуются не задумываясь.

## Срезы: s[a:b]

Оператор среза (*slicing*) берёт кусок слайса — с индекса `a` **включительно** до `b` **не включительно**:

```go
s := []int{10, 20, 30, 40, 50}
fmt.Println(s[1:4])   // [20 30 40] — индексы 1, 2, 3
fmt.Println(s[:2])    // [10 20]    — с начала
fmt.Println(s[2:])    // [30 40 50] — до конца
fmt.Println(s[:])     // [10 20 30 40 50] — весь
```

Длина куска — `b − a`. Логика «включительно-не включительно» такая же, как у `for i := a; i < b; i++`.

## Ловушка: срез — это окно, а не копия

Самое важное знание уровня. Слайс не хранит элементы сам — он **смотрит** на подлежащий массив (*underlying array*). Срез создаёт новое окно в **ту же** память:

```go
a := []int{1, 2, 3}
b := a[:2]        // b смотрит в ту же память, что и a
b[0] = 99
fmt.Println(a)    // [99 2 3] — изменился и a!
```

То же самое при присваивании слайса переменной и передаче в функцию: копируется только «окно» (указатель + длина), но не сами элементы. Изменили элемент через копию — изменили оригинал.

Нужна настоящая независимая копия? Для этого есть `copy`:

```go
a := []int{1, 2, 3}
b := make([]int, len(a))  // приготовили место
copy(b, a)                // скопировали элементы: copy(куда, откуда)
b[0] = 99
fmt.Println(a)            // [1 2 3] — оригинал цел
fmt.Println(b)            // [99 2 3]
```

`copy` копирует минимум из двух длин — поэтому место в `b` нужно выделить заранее через `make`.

## range по слайсу

`range` выдаёт пару: индекс и значение элемента.

```go
nums := []int{10, 20, 30}
for i, v := range nums {
    fmt.Println(i, v)
}
// 0 10
// 1 20
// 2 30
```

Не нужен индекс — на его место ставят пустой идентификатор `_` (*blank identifier*):

```go
sum := 0
for _, v := range nums {
    sum += v
}
fmt.Println(sum) // 60
```

Нужен только индекс — вторую переменную просто не пишите: `for i := range nums`.

> [!WARNING]
> Переменная `v` — **копия** элемента. Изменение `v` не трогает слайс:
>
> ```go
> for _, v := range nums {
>     v *= 2                // изменилась копия и тут же забылась
> }
> fmt.Println(nums)         // [10 20 30] — без изменений!
> ```
>
> Чтобы изменить элементы, пишите по индексу:
>
> ```go
> for i := range nums {
>     nums[i] *= 2
> }
> fmt.Println(nums)         // [20 40 60]
> ```

## Слайсы и функции

Функция принимает слайс как обычный параметр:

```go
func Sum(nums []int) int {
    sum := 0
    for _, v := range nums {
        sum += v
    }
    return sum
}

func main() {
    fmt.Println(Sum([]int{3, 4, 5})) // 12
    fmt.Println(Sum(nil))            // 0 — nil-слайс тоже ок
}
```

И может возвращать слайс — например, построить новый из старого:

```go
func Doubled(nums []int) []int {
    res := make([]int, 0, len(nums)) // пустой, но место подготовлено
    for _, v := range nums {
        res = append(res, v*2)
    }
    return res
}
```

Помните про «окно»: внутри функции `nums[i] = ...` изменит слайс вызывающего. Хотите этого избежать — стройте и возвращайте новый слайс, как `Doubled`.

## Типичные ошибки новичка

| Код | Что случится | Как чинить |
|---|---|---|
| `append(s, x)` без присваивания | ошибка компиляции: результат не используется | `s = append(s, x)` |
| `s[len(s)]` | `panic: index out of range` | последний элемент — `s[len(s)-1]` |
| `var s []int; s[0] = 1` | паника: у nil-слайса нет элементов | добавлять через `append` или создать `make([]int, n)` |
| `b := a; b[0] = 9` — а `a` испортился | слайсы делят одну память | явная копия: `make` + `copy` |
| `v *= 2` внутри `range` ничего не меняет | `v` — копия | менять по индексу: `s[i] *= 2` |

## Запомнить

- Массив — фиксированная длина, слайс — растёт через `append`; в 99% случаев нужен слайс.
- `s = append(s, x)` — всегда с присваиванием обратно.
- `len` — сколько есть; `cap` — сколько влезет без переезда; индексы `0..len-1`.
- `s[a:b]` — с `a` включительно по `b` не включительно; это окно в ту же память, не копия.
- Настоящая копия: `b := make([]int, len(a)); copy(b, a)`.
- `for i, v := range s` — индекс и копия значения; менять элементы — только через `s[i]`.
- nil-слайс (`var s []int`) дружит с `len`, `range` и `append` — паникует только индексация.
