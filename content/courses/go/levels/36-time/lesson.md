# Пакет time — моменты и длительности

Время пронизывает любую настоящую программу: отметки в логах, срок жизни кэша, расписание задач, «сколько занял запрос». В секции про горутины вы уже пользовались временем на бегу — `time.Sleep`, `time.After`, `context.WithTimeout(ctx, 2*time.Second)`. Пора познакомиться с пакетом `time` по-настоящему. Он стоит на двух китах: `time.Time` — **момент** времени («8 марта 2026, 21:30») и `time.Duration` — **длительность** («полтора часа»). Не путать их — половина успеха.

## time.Time — момент времени

Текущий момент выдаёт `time.Now()`, а конкретный собирается функцией `time.Date`:

```go
now := time.Now() // сейчас, в местной зоне

t := time.Date(2026, time.March, 8, 21, 30, 0, 0, time.UTC)
//             год   месяц       день ч   мин сек нсек зона
fmt.Println(t) // 2026-03-08 21:30:00 +0000 UTC
```

Из момента можно достать любой компонент — и узнать день недели:

```go
fmt.Println(t.Year(), t.Month(), t.Day()) // 2026 March 8
fmt.Println(t.Hour(), t.Minute())         // 21 30
fmt.Println(t.Weekday())                  // Sunday
```

Обратите внимание: месяц (*month*) — не число, а отдельный тип `time.Month` с константами `time.January` … `time.December`; день недели — тип `time.Weekday` (`time.Sunday` … `time.Saturday`). Печатаются они словами, а сравниваются как обычные константы: `t.Weekday() == time.Sunday`.

> [!NOTE]
> Нулевое значение `time.Time{}` — 1 января года 1. Проверить, что время «не заполнено», можно методом `t.IsZero()` — пригодится при обработке ошибок разбора.

## time.Duration — длительность

Под капотом `time.Duration` — всего лишь `int64`, число **наносекунд** (*nanoseconds*). Но благодаря константам `time.Second`, `time.Minute`, `time.Hour` длительности читаются как проза:

```go
d := 90 * time.Minute

fmt.Println(d)         // 1h30m0s — «умная» печать
fmt.Println(d.Hours()) // 1.5
fmt.Println(2 * time.Second)          // 2s
fmt.Println(1500 * time.Millisecond)  // 1.5s
```

Методы `Hours()`, `Minutes()`, `Seconds()` возвращают `float64` — целиком, а не «компонент»: у `2h15m` метод `Minutes()` вернёт `135`, а не `15`.

> [!WARNING]
> `90 * time.Minute` работает потому, что `90` — нетипизированная константа. А вот с переменной `n int` выражение `n * time.Minute` **не скомпилируется**: типы разные. Конвертируйте явно: `time.Duration(n) * time.Minute`.

## Арифметика: Add, Sub, Since, AddDate

Правила простые, как физика: момент + длительность = момент; момент − момент = длительность.

```go
start := time.Date(2026, time.March, 8, 21, 30, 0, 0, time.UTC)

end := start.Add(90 * time.Minute)
fmt.Println(end)            // 2026-03-08 23:00:00 +0000 UTC
fmt.Println(end.Sub(start)) // 1h30m0s
```

Для «сколько прошло с момента t» есть сокращение `time.Since(t)` — то же самое, что `time.Now().Sub(t)`. Классика замера:

```go
start := time.Now()
doWork()
fmt.Println("заняло:", time.Since(start))
```

Годы, месяцы и дни прибавляет `AddDate(годы, месяцы, дни)` — она учитывает календарь:

```go
fmt.Println(start.AddDate(0, 0, 30).Format("2006-01-02")) // 2026-04-07
```

Но у календаря есть острый угол — **нормализация** (*normalization*): 31 января + 1 месяц = «31 февраля», которого нет, и Go честно продолжает счёт — получается 3 марта:

```go
jan31 := time.Date(2026, time.January, 31, 0, 0, 0, 0, time.UTC)
fmt.Println(jan31.AddDate(0, 1, 0).Format("2006-01-02")) // 2026-03-03
```

Если нужен «последний день следующего месяца» — это придётся выразить явно, автоматика тут не на вашей стороне.

## Сравнение: Before, After, Equal — но не ==

```go
fmt.Println(start.Before(end)) // true
fmt.Println(end.After(start))  // true
fmt.Println(end.Equal(end))    // true
```

Почему не `==`? Структура `time.Time` хранит не только момент, но и зону, и показания монотонных часов. Один и тот же миг в разных представлениях — `12:00 UTC` и `15:00 MSK` — это `==`-разные структуры, хотя `Equal` честно скажет `true`:

```go
msk := time.FixedZone("MSK", 3*60*60)
a := time.Date(2026, time.March, 8, 12, 0, 0, 0, time.UTC)
b := time.Date(2026, time.March, 8, 15, 0, 0, 0, msk)

fmt.Println(a == b)      // false — разные структуры…
fmt.Println(a.Equal(b))  // true  — …но один момент!
```

Правило: моменты сравниваем только методами `Equal`, `Before`, `After`.

## Форматирование: эталонная дата 2006-01-02

В большинстве языков дату форматируют шаблонами вида `YYYY-MM-DD`. Go пошёл своим путём: вы показываете, как должна выглядеть **одна конкретная дата** — эталонная (*reference date*):

```
Mon Jan 2 15:04:05 MST 2006
```

Почему именно она? В американском порядке записи это 1-2-3-4-5-6-7: месяц `1`, день `2`, час `3` (15:00 = 3 часа дня), минуты `4`, секунды `5`, год `6`, зона `7`. Запомнили последовательность — восстановите любой шаблон:

```go
t := time.Date(2026, time.March, 8, 21, 30, 0, 0, time.UTC)

fmt.Println(t.Format("2006-01-02"))              // 2026-03-08
fmt.Println(t.Format("02.01.2006"))              // 08.03.2026
fmt.Println(t.Format("15:04"))                   // 21:30
fmt.Println(t.Format("Monday, 2 January 2006"))  // Sunday, 8 March 2026
fmt.Println(t.Format(time.RFC3339))              // 2026-03-08T21:30:00Z
```

Шпаргалка по «глаголам» эталонной даты:

| В шаблоне | Что означает | Пример вывода |
|---|---|---|
| `2006` | год полностью | `2026` |
| `06` | год двумя цифрами | `26` |
| `01` / `1` | месяц числом (с нулём / без) | `03` / `3` |
| `Jan` / `January` | месяц словом | `Mar` / `March` |
| `02` / `2` | день месяца | `08` / `8` |
| `Mon` / `Monday` | день недели | `Sun` / `Sunday` |
| `15` | часы, 24-часовой формат | `21` |
| `3` / `03` + `PM` | часы, 12-часовой формат | `9:30 PM` |
| `04` | минуты | `30` |
| `05` | секунды | `00` |
| `MST`, `-0700`, `Z07:00` | часовой пояс | `UTC`, `+0000`, `Z` |

Для обмена данными не изобретайте шаблон — берите готовую константу `time.RFC3339` (`"2006-01-02T15:04:05Z07:00"`): этот формат понимают JSON-API, базы и логи всего мира.

> [!WARNING]
> `t.Format("YYYY-MM-DD")` не упадёт и не предупредит — Go просто не найдёт в строке компонентов эталонной даты и напечатает буквально `YYYY-MM-DD`. Молча. Увидели в выводе куски шаблона вместо даты — вспомните про 2006-01-02.

## Разбор строк: Parse и ParseDuration

Обратная операция — из строки в момент — делается той же эталонной датой:

```go
t, err := time.Parse("2006-01-02", "2026-03-08")
if err != nil {
    // строка не подошла под шаблон
}
fmt.Println(t) // 2026-03-08 00:00:00 +0000 UTC
```

`Parse` возвращает ошибку — и её **обязательно** проверять, как вы привыкли в секции про ошибки. Строка не совпала с шаблоном — получите нулевое время и внятное объяснение:

```go
_, err := time.Parse("2006-01-02", "08.03.2026")
fmt.Println(err)
// parsing time "08.03.2026" as "2006-01-02": cannot parse "08.03.2026" as "2006"
```

Проигнорируете ошибку — дальше по программе поедет фальшивый момент `0001-01-01`, и искать причину будете далеко от места аварии.

Длительности разбирает `time.ParseDuration` — понимает `"ns"`, `"us"`, `"ms"`, `"s"`, `"m"`, `"h"` и их комбинации:

```go
d, err := time.ParseDuration("1h30m")
fmt.Println(d, err) // 1h30m0s <nil>
```

Суток в этом списке нет: `ParseDuration("2d")` вернёт ошибку `unknown unit "d"`. Дни — это календарь (см. `AddDate`), а не длительность: из-за перевода часов сутки не всегда длятся 24 часа.

## UTC и местное время — коротко

`time.Now()` возвращает время в местной зоне машины, методы `t.UTC()` и `t.Local()` переводят момент между представлениями (сам миг не меняется — вспомните пример с `Equal`). Практическое правило индустрии: **в базах данных и логах храните UTC**, а в местное время переводите только при показе пользователю. Тогда сервер в Москве и сервер в Сиэтле пишут одинаковые отметки, и события можно сортировать без головоломок. Глубже в часовые пояса (`time.LoadLocation`) нырнём, когда понадобится, — для этого уровня достаточно UTC.

А со «временем как будильником» вы уже знакомы: `time.Sleep(d)`, `time.After(d)` и `context.WithTimeout` принимают именно `time.Duration` — теперь вы знаете, что передаёте им.

## Типичные ошибки новичка

| Код | Что случится | Как чинить |
|---|---|---|
| `t.Format("YYYY-MM-DD")` | молча напечатает буквально `YYYY-MM-DD` | шаблон — только из компонентов `2006-01-02 15:04:05` |
| `t1 == t2` | `false` для одного и того же мига в разных зонах | `Equal`, `Before`, `After` |
| `t, _ := time.Parse(...)` | при кривой строке дальше поедет `0001-01-01` | всегда проверять `err` |
| `jan31.AddDate(0, 1, 0)` | нормализация: 3 марта, а не конец февраля | прибавлять дни или проверять `Day()` результата |
| `n * time.Second` с переменной `n int` | не скомпилируется: разные типы | `time.Duration(n) * time.Second` |
| `time.ParseDuration("2d")` | ошибка: суток в единицах нет | `"48h"` — или календарный `AddDate(0, 0, 2)` |

## Запомнить

- `time.Time` — момент, `time.Duration` — длительность (`int64` наносекунд). Момент + длительность = момент (`Add`); момент − момент = длительность (`Sub`); `time.Since(t)` — «сколько прошло».
- Компоненты момента: `Year()`, `Month()` (тип `time.Month`!), `Day()`, `Hour()`, `Weekday()`. Календарная арифметика — `AddDate(г, м, д)`, помните про нормализацию 31-х чисел.
- Моменты сравнивают `Equal`/`Before`/`After`, не `==`.
- Формат и разбор — через эталонную дату `2006-01-02 15:04:05` (мнемоника 1-2-3-4-5-6-7); для обмена — `time.RFC3339`.
- `time.Parse` и `time.ParseDuration` возвращают ошибку — проверять всегда; суток (`"d"`) в `ParseDuration` нет.
- В базах и логах — UTC; местное время — только для показа человеку.
