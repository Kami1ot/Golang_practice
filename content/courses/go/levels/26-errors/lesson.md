# Ошибки в Go — просто значения

С интерфейсом `error` вы уже знакомы: любой тип с методом `Error() string`, возвращается последним результатом, `nil` — «всё хорошо». Пришло время главного: **как с ошибками живут**. В Go нет исключений (*exceptions*) — ошибка не летит через полпрограммы, а возвращается из функции, как обычное значение. Эта секция научит создавать ошибки, проверять их, пробрасывать наверх и не терять по дороге.

## Философия: ошибка — часть ответа

В языках с исключениями функция «бросает» ошибку, и та раскручивает стек, пока кто-нибудь не поймает. В Go функция честно отвечает: «вот результат И вот ошибка — смотри сам»:

```go
func Divide(a, b int) (int, error) {
	if b == 0 {
		return 0, errors.New("деление на ноль")
	}
	return a / b, nil
}
```

Плюсы такого подхода видны прямо в сигнатуре: `(int, error)` кричит «я могу не справиться!» — и компилятор заставит вызывающего хотя бы принять ошибку. Никаких сюрпризов из глубины стека.

## Создание ошибок: errors.New и fmt.Errorf

Для фиксированного текста — `errors.New` из пакета `errors`:

```go
err := errors.New("файл не найден")
fmt.Println(err) // файл не найден
```

Когда в сообщение нужно вставить данные — `fmt.Errorf`: те же глаголы, что у `Printf`, а результат — готовая ошибка:

```go
age := 200
err := fmt.Errorf("возраст %d вне диапазона [0, 150]", age)
fmt.Println(err) // возраст 200 вне диапазона [0, 150]
```

> [!NOTE]
> Конвенции текста ошибок: с маленькой буквы, без точки и восклицаний в конце («file not found», а не «File not found!»). Причина: сообщения часто склеиваются в цепочки вида `открытие конфига: файл не найден` — заглавные буквы и точки в середине выглядели бы неряшливо.

## Идиома if err != nil: проверяй сразу

Канонический вид работы с функцией, возвращающей ошибку:

```go
result, err := Divide(10, 2)
if err != nil {
	fmt.Println("не получилось:", err)
	return
}
fmt.Println(result) // 5 — сюда попадаем только при успехе
```

Три правила, которые делают код предсказуемым:

1. **Проверяйте ошибку сразу** после вызова — не через пять строк.
2. **При ошибке выходите рано** (`return`) — это называется ранним выходом (*early return*).
3. **Не трогайте результат до проверки**: при ошибке в нём лежит бессмысленное нулевое значение.

Благодаря раннему выходу «счастливый путь» (*happy path*) программы читается сверху вниз по левому краю, а обработка неудач не съедает основную логику.

## Пробрасывание: ошибка едет наверх

Что делать функции, если ошибку вернул КТО-ТО, кого она вызвала? Чаще всего — прекратить работу и передать ошибку своему вызывающему:

```go
func ParseAge(s string) (int, error) {
	n, err := strconv.Atoi(s) // строка → число, знакомо с уровня про строки
	if err != nil {
		return 0, err // не разобрались сами — пусть решает вызывающий
	}
	if n < 0 || n > 150 {
		return 0, fmt.Errorf("возраст %d вне диапазона [0, 150]", n)
	}
	return n, nil
}
```

Здесь оба вида: чужая ошибка (`strconv.Atoi` не смог) пробрасывается как есть, своя (диапазон) — создаётся на месте. Наверху всё сходится в одну проверку:

```go
age, err := ParseAge("сто")
if err != nil {
	fmt.Println("анкета не принята:", err)
	return
}
fmt.Println("возраст принят:", age)
// анкета не принята: strconv.Atoi: parsing "сто": invalid syntax
```

Цепочка `main → ParseAge → strconv.Atoi` вернула ошибку с самого дна — и никто по дороге её не потерял.

## Ошибки — значения: с ними можно всё

Раз ошибка — обычное значение, её можно класть в переменную, сравнивать, собирать в слайс:

```go
var lastErr error // nil — ошибок пока не было

for _, s := range []string{"12", "тридцать", "7"} {
	if _, err := ParseAge(s); err != nil {
		lastErr = err
	}
}

if lastErr != nil {
	fmt.Println("хотя бы одна запись плохая:", lastErr)
}
```

Никакой специальной магии «обработки исключений» — обычные переменные, обычные `if`. В этом вся суть: **обработка ошибок в Go — это просто программирование**.

## Игнорировать можно — но только осознанно

Go заставляет принять ошибку, но не заставляет её проверять. Подчёркивание отбрасывает её:

```go
n, _ := strconv.Atoi(s) // ошибки не будет? УВЕРЕНЫ?
```

Это законно и изредка оправдано (значение по умолчанию устраивает). Но каждый такой `_` — осознанное решение, а не лень: молча проглоченная ошибка всплывёт позже в виде непонятного поведения, и отлаживать её будет мучительно.

> [!WARNING]
> Худший вариант — принять ошибку в переменную и забыть проверить: `n, err := strconv.Atoi(s); использовать(n)`. Компилятор поймает НЕиспользованную переменную, только если `err` больше нигде не участвует; в длинной функции, где `err` переприсваивается, пропущенная проверка живёт незамеченной. Привычка: вызвал → сразу `if err != nil`.

## А что вернуть вместе с ошибкой?

Первый результат при ошибке — нулевое значение типа: `0`, `""`, `nil`. Вызывающий всё равно не должен на него смотреть:

```go
func FindIndex(nums []int, target int) (int, error) {
	for i, n := range nums {
		if n == target {
			return i, nil
		}
	}
	return 0, fmt.Errorf("значение %d не найдено", target)
}
```

Ноль здесь — не «нашлось на позиции 0», а заглушка: договор «сначала проверь err» отменяет двусмысленность.

## Типичные ошибки новичка

| Код | Что случится | Как чинить |
|---|---|---|
| использовать `result` до проверки `err` | при ошибке в result нулевой мусор — логика ломается молча | сначала `if err != nil`, потом result |
| `if err == nil { ... большой блок ... } else { return }` | счастливый путь уехал вглубь, читать тяжело | ранний выход: `if err != nil { return ... }` |
| `n, _ := strconv.Atoi(s)` не задумываясь | ошибка проглочена: «тридцать» молча стало 0 | `_` — только когда осознанно всё равно |
| `errors.New(fmt.Sprintf("возраст %d", n))` | работает, но зачем два шага | `fmt.Errorf("возраст %d", n)` |
| `return -1, fmt.Errorf(...)` как «код ошибки» | вызывающий начнёт проверять магические -1 вместо err | при ошибке возвращайте нулевое значение |
| текст «Ошибка: Файл Не Найден.» | в цепочках сообщений появятся заглавные и точки посреди фразы | с маленькой буквы, без точки |

## Запомнить

- Исключений нет: ошибка возвращается последним результатом и проверяется явно — `if err != nil`.
- `errors.New("текст")` — фиксированное сообщение; `fmt.Errorf("формат %d", x)` — сообщение с данными.
- Проверяйте ошибку сразу после вызова; при ошибке — ранний выход `return`.
- Не смотрите на результат до проверки err: там нулевое значение-заглушка.
- Не смогли обработать — пробросьте наверх: `return 0, err`.
- `_` вместо err — осознанное решение в редких случаях, а не привычка.
- Текст ошибки: с маленькой буквы, без точки в конце — он будет частью цепочки.
