# Привет, Go!

Добро пожаловать! Этот уровень — фундамент всего курса: вы узнаете, что за язык Go, из чего состоит любая программа на нём и как её запустить. Не торопитесь — всё, что здесь написано, понадобится в каждом следующем уровне.

## Что такое Go и зачем он нужен

Go (его ещё называют Golang) придумали в Google в 2009 году. Авторы устали от двух крайностей: «быстрые, но сложные» языки вроде C++ и «простые, но медленные» вроде Python. Go — попытка взять лучшее из обоих миров:

- **Компилируемый** (*compiled*): программа целиком переводится в машинный код **до** запуска. Отсюда скорость — и ещё один бонус: множество ошибок компилятор (*compiler*) находит раньше, чем программа вообще запустится.
- **Статически типизированный** (*statically typed*): тип каждой переменной известен заранее. Опечатались — узнаете сразу, а не в три часа ночи на сервере.
- **Простой**: в Go всего 25 ключевых слов (для сравнения: в C++ их больше 90). Язык можно выучить целиком — и этот курс именно это и делает.

На Go написаны Docker, Kubernetes, Telegram-боты половины интернета и серверная часть многих крупных сервисов. Это язык номер один для сетевых сервисов и инфраструктуры.

> [!NOTE]
> «Компилируемый» — не значит «неудобный». Компилятор Go настолько быстрый, что цикл «поменял код → запустил» ощущается как в скриптовых языках.

## Минимальная программа

Вот самая маленькая осмысленная программа на Go. Присмотритесь к каждой строке — дальше разберём их по очереди:

```go
package main

import "fmt"

func main() {
    fmt.Println("Привет, Go!")
}
// Вывод:
// Привет, Go!
```

### package main — «где я живу»

Весь код в Go организован в пакеты (*package*). Первая строка любого `.go`-файла объявляет, к какому пакету он относится. Пакет с именем `main` — особенный: только из него можно собрать **исполняемую программу**. Библиотеки живут в пакетах с другими именами (`fmt`, `strings`, `math`...).

### import "fmt" — «чьими инструментами пользуюсь»

`import` подключает чужой пакет, чтобы пользоваться его функциями. Пакет `fmt` (от *format*) — из стандартной библиотеки (*standard library*), в нём живут все функции ввода-вывода: `Println`, `Printf`, `Scan`...

Обращаются к функции через имя пакета и точку: `fmt.Println`. Так всегда видно, откуда функция взялась.

### func main() — «отсюда всё начинается»

`func` объявляет функцию (*function*) — именованный кусок кода. Функция `main` в пакете `main` — точка входа (*entry point*): выполнение программы всегда начинается с первой строки её тела и заканчивается на последней.

Тело функции заключено в фигурные скобки `{ }`. Всё, что программа «делает», живёт внутри функций.

## Запуск: go run и go build

У компилируемого языка есть два режима работы с программой:

| Команда | Что делает | Когда использовать |
|---|---|---|
| `go run main.go` | компилирует во временную папку и сразу запускает | во время разработки: быстро проверить |
| `go build main.go` | создаёт исполняемый файл (`main.exe` на Windows) | когда программа готова: файл можно отдать кому угодно |

```
$ go run main.go
Привет, Go!

$ go build main.go
$ ./main
Привет, Go!
```

Собранный файл — самодостаточный: на машине пользователя не нужен ни Go, ни библиотеки. Это одна из причин любви к Go в мире серверов.

> [!NOTE]
> На этой платформе кнопка «Запустить» делает за вас именно `go build` + запуск. Но понимать, что происходит под капотом, полезно с первого дня.

## fmt.Println: вывод с новой строкой

`fmt.Println` (*print line*) печатает свои аргументы и **добавляет перевод строки** в конце. Аргументов может быть сколько угодно — они разделяются пробелами:

```go
fmt.Println("Привет!")
fmt.Println("Go создали в", 2009, "году")
fmt.Println(2 + 2)
// Вывод:
// Привет!
// Go создали в 2009 году
// 4
```

Заметьте: числа и текст можно смешивать, а выражение `2 + 2` вычисляется до печати.

Вызов вовсе без аргументов печатает просто пустую строку (один перевод строки):

```go
fmt.Println("строка 1")
fmt.Println()
fmt.Println("строка 3")
// Вывод:
// строка 1
//
// строка 3
```

## fmt.Print: вывод без перевода строки

У `Println` есть брат — `fmt.Print`. Он печатает аргументы и **не** переходит на новую строку. Следующий вывод продолжится там же:

```go
fmt.Print("Загрузка")
fmt.Print(".")
fmt.Print(".")
fmt.Println(".")
// Вывод:
// Загрузка...
```

Три `Print` напечатали всё в одну строку, а завершающий `Println` поставил точку и перевёл строку.

| Функция | Перевод строки в конце | Пробелы между аргументами |
|---|---|---|
| `fmt.Println(a, b)` | да | всегда |
| `fmt.Print(a, b)` | нет | только между числами |

## Комментарии

Комментарий (*comment*) — текст для людей, компилятор его полностью игнорирует:

```go
// Однострочный комментарий: до конца строки.

/*
   Многострочный комментарий:
   всё между звёздочками.
*/

fmt.Println("код") // комментарий можно писать и после кода
```

Хороший комментарий объясняет **зачем**, а не пересказывает **что**: `// ждём 5 секунд, чтобы сервер успел стартовать` полезнее, чем `// вызываем Sleep`.

## gofmt: единый стиль без споров

В Go не бывает споров «пробелы или табы» и «где ставить скобку»: официальная утилита `gofmt` форматирует код за всех и одинаково. Отступы — **табы**, скобка `{` — на той же строке. Редакторы запускают `gofmt` автоматически при сохранении.

Следствие: любой чужой Go-код выглядит знакомо. Для новичка это подарок — читаемых примеров вокруг море.

## Типичные ошибки новичка

Компилятор Go — строгий, но честный учитель: он всегда пишет **файл, строку и причину**. Разберём три классики.

### 1. Код вне функции

Новичок пишет:

```go
package main

import "fmt"

fmt.Println("Привет")   // код прямо в файле, вне функции
```

Компилятор ответит:

```
syntax error: non-declaration statement outside function body
```

**Почему:** на уровне пакета могут жить только объявления (функций, переменных, констант). Действия — только внутри функций. **Как чинить:** заверните код в `func main() { ... }`.

### 2. Неиспользованный import

```go
package main

import (
    "fmt"
    "os"      // подключили, но нигде не используем
)

func main() {
    fmt.Println("Привет")
}
```

```
"os" imported and not used
```

**Почему:** в Go неиспользованный импорт — это **ошибка**, а не предупреждение. Язык принуждает держать код чистым. **Как чинить:** удалить лишнюю строку импорта (редактор с gofmt-надстройкой `goimports` делает это сам).

### 3. Фигурная скобка на новой строке

Привычка из других языков:

```go
func main()
{
    fmt.Println("Привет")
}
```

```
syntax error: unexpected semicolon or newline before {
```

**Почему:** Go автоматически ставит точку с запятой в конце каждой строки, и после `func main()` без `{` она разрывает объявление пополам. **Как чинить:** `{` всегда на той же строке, что и `func`, `if`, `for`. Это не стиль на выбор — это правило языка.

> [!WARNING]
> Ещё одна ловушка: `fmt.println` со строчной буквы не существует — компилятор скажет `undefined: fmt.println (but have Println)` и даже подскажет правильное имя. Из чужого пакета доступно только то, что начинается с **заглавной** буквы: `Println`, `Print`, `Printf`.

## Запомнить

- Go — компилируемый и статически типизированный: быстрый, а ошибки ловятся до запуска.
- Каждый файл начинается с `package ...`; исполняемая программа — это пакет `main` с функцией `main`.
- `import "fmt"` подключает пакет; функции зовутся `имяПакета.Функция`, с заглавной буквы.
- `go run` — скомпилировать и сразу запустить; `go build` — собрать исполняемый файл.
- `fmt.Println` добавляет перевод строки и разделяет аргументы пробелами; `fmt.Print` — не переводит строку.
- Код живёт только внутри функций; неиспользованный import — ошибка; `{` — на той же строке.
- Комментарии: `//` до конца строки, `/* ... */` — блоком.
- `gofmt` форматирует код за вас: отступы — табы, стиль — единый во всём мире Go.
