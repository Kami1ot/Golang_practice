Основная задача: соберите настоящий мини-API — маршрутизатор с двумя ручками.

Реализуйте функцию:

```go
func NewServer() http.Handler
```

Она возвращает `ServeMux` с маршрутами в стиле Go 1.22+ (метод прямо в шаблоне):

| Маршрут | Ответ |
|---|---|
| `GET /ping` | текст `pong`, статус 200 |
| `GET /users/{id}` | JSON пользователя из мапы `users`, статус 200 |

Правила для `/users/{id}`:

- `id` не превращается в число (`strconv.Atoi` вернул ошибку) → статус 400;
- число есть, но такого пользователя нет в мапе `users` → статус 404;
- пользователь найден → заголовок `Content-Type: application/json` и JSON вида `{"id":1,"name":"Ада"}` — кодируйте структуру `User` через `json.NewEncoder(w).Encode`.

Мапа `users` и структура `User` уже объявлены в заготовке — не меняйте их. Понадобятся import'ы `encoding/json`, `strconv` и `fmt`.

Неподходящий метод отклонит сам mux: на `POST /ping` он ответит 405 без вашей помощи — если метод указан в шаблоне. Тесты это проверяют, как и все ветки `/users/{id}`; а `/ping` дополнительно гоняется через настоящий тестовый сервер `httptest.NewServer` — знакомый по уровню про клиента.

Не меняйте имя и сигнатуру функции.
