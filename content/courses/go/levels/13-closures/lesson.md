# Функции как значения и замыкания

До этого уровня функции жили по одним правилам: объявили на уровне пакета — вызвали по имени. Пора открыть один из главных секретов Go: функция — это **значение первого класса** (*first-class value*). Её можно положить в переменную, передать в другую функцию аргументом, вернуть из функции результатом — ровно как число или строку. На этом приёме держится половина стандартной библиотеки, а вишенка на торте — замыкания (*closures*): функции с собственной памятью.

## Функция в переменной

Функция кладётся в переменную по имени — **без скобок**:

```go
package main

import "fmt"

func double(x int) int {
	return x * 2
}

func main() {
	f := double          // без скобок: кладём САМУ функцию
	fmt.Println(f(5))    // 10
	fmt.Println(f(7))    // 14
}
```

Теперь `f` и `double` — два имени одной и той же функции: вызывать можно через любое.

Скобки решают всё:

| Запись | Что окажется в переменной | Тип |
|---|---|---|
| `f := double` | сама функция | `func(int) int` |
| `v := double(3)` | результат вызова — число 6 | `int` |

> [!WARNING]
> Самая частая путаница уровня: `double` — функция, а `double(3)` — уже её РЕЗУЛЬТАТ. Написали скобки — вызов произошёл немедленно. `f := double(3)` положит в `f` число 6, и дальше `f(10)` не скомпилируется: число нельзя вызвать.

## Функциональный тип

Раз функция — значение, у неё есть тип. Функциональный тип (*function type*) записывается как сигнатура без имени функции и без имён параметров:

```go
var op func(int) int    // «функция: принимает int, возвращает int»
op = double
fmt.Println(op(21))     // 42
```

Как читать такие типы:

| Тип | Читается |
|---|---|
| `func(int) int` | принимает int, возвращает int |
| `func() int` | без параметров, возвращает int |
| `func(string, int) bool` | принимает string и int, возвращает bool |
| `func(int)` | принимает int, ничего не возвращает |

Типы должны совпадать в точности: `func(int) int` и `func(int) string` — разные типы, компилятор их не перепутает.

> [!WARNING]
> Нулевое значение функционального типа — `nil`. Вызов ещё не заполненной переменной (`var op func(int) int; op(1)`) уронит программу паникой во время выполнения. Сначала присвоить функцию, потом вызывать.

## Анонимные функции

Функцию можно создать прямо в выражении, не давая ей имени — это анонимная функция (*anonymous function*):

```go
square := func(x int) int {
	return x * x
}
fmt.Println(square(4))   // 16
fmt.Println(square(9))   // 81
```

Синтаксис тот же `func`, только без имени — и объявлять её можно прямо внутри другой функции, хоть в `main`. А если функция нужна один-единственный раз, её вызывают сразу на месте рождения, дописав скобки с аргументами:

```go
greeting := func(name string) string {
	return "Привет, " + name + "!"
}("Гофер")               // ← объявили и тут же вызвали

fmt.Println(greeting)    // Привет, Гофер!
```

В `greeting` попала уже строка — результат вызова, а не функция.

## Функция как параметр

Функциональный тип может стоять в списке параметров — тогда в функцию передают другую функцию как обычный аргумент. Передаваемую функцию называют колбэком (*callback*). Классика жанра — «применить операцию к каждому элементу слайса»:

```go
func transform(nums []int, f func(int) int) []int {
	res := make([]int, 0, len(nums))
	for _, v := range nums {
		res = append(res, f(v))    // вызываем то, что передали снаружи
	}
	return res
}

func main() {
	nums := []int{1, 2, 3}
	fmt.Println(transform(nums, double))    // [2 4 6] — передали по имени
	fmt.Println(transform(nums, func(x int) int {
		return x * x
	}))                                     // [1 4 9] — передали анонимную
}
```

Логика обхода написана один раз, а операций — сколько угодно: удвоение, квадрат, что захотите. Именно так устроены многие функции стандартной библиотеки, до которых мы ещё доберёмся.

## Функция как результат: фабрика

Функцию можно и вернуть. Функцию, производящую другие функции, называют фабрикой (*factory*):

```go
func makeAdder(n int) func(int) int {
	return func(x int) int {
		return x + n    // n пришла из makeAdder — и осталась жить
	}
}

func main() {
	add5 := makeAdder(5)
	add100 := makeAdder(100)
	fmt.Println(add5(1))     // 6
	fmt.Println(add5(10))    // 15
	fmt.Println(add100(1))   // 101
}
```

Стоп. `makeAdder(5)` давно завершилась — а `add5` до сих пор откуда-то знает, что `n == 5`. Как?!

## Замыкание: функция с памятью

Анонимная функция, созданная внутри другой, **захватывает** переменные из места своего рождения. Такая функция называется замыканием (*closure*): она «замыкает» на себя внешние переменные, и Go сохраняет их живыми, пока живо само замыкание — даже после выхода из внешней функции.

Классика — счётчик:

```go
func makeCounter() func() int {
	count := 0
	return func() int {
		count++          // замыкание меняет ВНЕШНЮЮ переменную
		return count
	}
}

func main() {
	next := makeCounter()
	fmt.Println(next())  // 1
	fmt.Println(next())  // 2
	fmt.Println(next())  // 3
}
```

Переменная `count` родилась в `makeCounter`, но не исчезла при выходе из неё: возвращённое замыкание держит её при себе и меняет при каждом вызове. Снаружи до `count` не добраться никак — только через сам счётчик. Аккуратная приватная память.

## У каждого вызова фабрики — своё окружение

Каждый вызов `makeCounter()` создаёт **новую** переменную `count`. Два счётчика — два независимых окружения:

```go
a := makeCounter()
b := makeCounter()
fmt.Println(a())    // 1
fmt.Println(a())    // 2
fmt.Println(b())    // 1 — у b СВОЙ count, он не слышал про a
fmt.Println(a())    // 3 — a продолжает со своего места
```

## Захватывается переменная, а не копия

Замыкание запоминает не значение на момент создания, а саму переменную — изменения видны в обе стороны:

```go
x := 10
show := func() {
	fmt.Println(x)
}
show()     // 10
x = 20
show()     // 20 — замыкание видит АКТУАЛЬНОЕ значение
```

И в обратную сторону — замыкание меняет внешнюю переменную:

```go
total := 0
add := func(n int) {
	total += n
}
add(3)
add(4)
fmt.Println(total)   // 7 — изменения из замыкания видны снаружи
```

> [!NOTE]
> Начиная с Go 1.22 переменная цикла `for` создаётся заново на КАЖДОЙ итерации — раньше она была одна на весь цикл, и все замыкания, созданные в цикле, захватывали её сообща. Эта знаменитая ловушка громче всего стреляла в связке с горутинами — когда доберёмся до них, вспомним это место: в современном Go она уже обезврежена.

## Типичные ошибки новичка

| Код | Что случится | Как чинить |
|---|---|---|
| `transform(nums, double(3))` | не компилируется: `double(3)` — число, а не функция | передавать по имени без скобок: `double` |
| `fmt.Println(next)` вместо `next()` | напечатается адрес вида `0x47b880`, а не число | не забывать скобки вызова: `next()` |
| `var op func(int) int` и сразу `op(1)` | паника: вызов nil-функции | сначала присвоить функцию, потом вызывать |
| счётчик в переменной уровня пакета | все счётчики делят одну память — «независимые» счётчики мешают друг другу | держать переменную ВНУТРИ фабрики |
| `op = someFunc` при несовпадающей сигнатуре | ошибка компиляции: разные функциональные типы | сигнатуры должны совпадать в точности |

## Запомнить

- Функция — значение первого класса: живёт в переменных, параметрах и результатах.
- Имя без скобок — сама функция; со скобками — немедленный вызов и его результат.
- Функциональный тип — сигнатура без имён: `func(int) int`.
- Анонимную функцию объявляют на месте; допишите `(аргументы)` — и она вызовется сразу.
- Замыкание захватывает ПЕРЕМЕННУЮ из места рождения, а не её копию: изменения видны в обе стороны.
- Каждый вызов фабрики создаёт новое окружение: два счётчика из `makeCounter` независимы.
- С Go 1.22 переменная `for` своя на каждой итерации — старая ловушка замыканий в цикле обезврежена.
