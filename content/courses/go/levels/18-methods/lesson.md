# Методы — данные обретают поведение

К этому уровню у вас есть структуры (данные) и функции (поведение), но живут они порознь: структура отдельно, функция `Area(r)` — отдельно. Метод (*method*) прикрепляет функцию к типу, и вызов превращается в `r.Area()` — «у прямоугольника спросили его площадь». Данные и их поведение наконец-то вместе, а заодно вы поймёте, почему одни методы меняют структуру, а другие — молча теряют изменения.

## Синтаксис: функция + получатель

Метод — это обычная функция, у которой между `func` и именем добавили ещё одну пару скобок. В них живёт получатель (*receiver*) — «владелец» метода:

```go
type Rect struct {
	W, H int
}

// (r Rect) — получатель: этот метод принадлежит типу Rect
func (r Rect) Area() int {
	return r.W * r.H
}
```

Внутри метода получатель `r` — обычная переменная типа `Rect`: поля читаются как всегда, через точку. А вызывается метод у конкретного значения:

```go
r := Rect{W: 3, H: 4}
fmt.Println(r.Area())   // 12
```

Читается слева направо: «у прямоугольника `r` возьми площадь». Никаких новых механизмов — только новый способ записать знакомое.

## Метод против обычной функции

Ту же работу умеет и обычная функция — сравните:

```go
// Обычная функция: прямоугольник передаём параметром
func AreaOf(r Rect) int {
	return r.W * r.H
}

// Метод: прямоугольник — получатель
func (r Rect) Area() int {
	return r.W * r.H
}

r := Rect{W: 3, H: 4}
fmt.Println(AreaOf(r))  // 12
fmt.Println(r.Area())   // 12 — то же самое, другая запись
```

Тело — идентичное, результат — одинаковый. Разница в стиле мышления: функция говорит «посчитай площадь ЭТОГО», метод — «этот тип УМЕЕТ считать свою площадь». Когда у типа появляется несколько операций (`r.Area()`, `r.Perimeter()`, `r.Scale(2)`), методы собирают их в аккуратный «набор умений» типа.

> [!NOTE]
> Метод не вызвать как функцию по одному имени: после `func (r Rect) Area()` запись `Area(r)` даст ошибку `undefined: Area`. Только через точку: `r.Area()`.

## Получатель-значение: метод работает с копией

Ключевой момент уровня. Получатель-значение (*value receiver*) — как обычный параметр функции: метод получает **копию**. Читать поля можно сколько угодно, а вот изменения умрут вместе с копией:

```go
func (r Rect) Scale(k int) { // r — КОПИЯ вызвавшего прямоугольника
	r.W *= k
	r.H *= k
}

r := Rect{W: 2, H: 3}
r.Scale(10)
fmt.Println(r.W, r.H)   // 2 3 — изменения пропали!
```

Программа компилируется, работает, не паникует — и тихо делает не то. Метод честно умножил стороны... у копии, которая исчезла при выходе из метода.

> [!WARNING]
> Value receiver, который присваивает что-то полям, — ловушка №1 этого уровня. Ошибки компиляции НЕТ, программа просто «не сохраняет» изменения. Увидели метод-модификатор без звёздочки у получателя — вот и виновник.

## Получатель-указатель: метод меняет оригинал

Чтобы метод менял вызвавшее значение, получателю нужен адрес — это получатель-указатель (*pointer receiver*). Одна звёздочка решает всё:

```go
func (r *Rect) Scale(k int) { // r — указатель на оригинал
	r.W *= k
	r.H *= k
}

r := Rect{W: 2, H: 3}
r.Scale(10)
fmt.Println(r.W, r.H)   // 20 30 — оригинал изменился
```

Внутри метода не нужно писать `(*r).W` — с уровня про указатели вы знаете, что Go разыменовывает указатель на структуру сам: `r.W` работает.

Классика жанра — счётчик, который копит состояние между вызовами:

```go
type Counter struct {
	value int
}

func (c *Counter) Inc() {
	c.value++
}

c := Counter{}
c.Inc()
c.Inc()
c.Inc()
fmt.Println(c.value)    // 3
```

С получателем-значением тот же счётчик навсегда остался бы нулём: каждый `Inc` увеличивал бы свежую копию.

> [!NOTE]
> Заметили? Мы написали `c.Inc()`, хотя `c` — не указатель, а обычная переменная. Go сам подставил адрес: `c.Inc()` для компилятора значит `(&c).Inc()`. Это работает для любой переменной (у неё есть адрес); а вот у временного значения вроде `Counter{}.Inc()` адреса нет — компилятор откажется.

## Какой получатель выбирать

| | `func (r Rect)` — значение | `func (r *Rect)` — указатель |
|---|---|---|
| Что получает метод | копию | адрес оригинала |
| Изменения полей | пропадают вместе с копией | сохраняются в оригинале |
| Копирование при вызове | вся структура | только адрес (дёшево) |
| Когда выбирать | метод только читает, структура небольшая | метод меняет состояние ИЛИ структура большая |

Правило на пальцах:

- метод **меняет** поля → указатель, без вариантов;
- структура **большая** (много полей, слайсы внутри) → указатель, чтобы не копировать её на каждый вызов;
- метод **только читает** маленькую структуру → значение.

> [!NOTE]
> Совет консистентности из практики Go: если хотя бы один метод типа — указательный, делайте указательными ВСЕ его методы. Смесь компилируется и работает, но тип с «полосатыми» получателями сложнее читать и легче сломать. В задачах этого уровня мы иногда смешиваем — специально, чтобы вы прочувствовали разницу.

## Собираем всё вместе: тип с набором умений

Полная программа — кошелёк, у которого есть и метод-модификатор, и метод-читатель:

```go
package main

import "fmt"

type Wallet struct {
	rub int
}

// Deposit меняет состояние — получатель-указатель.
func (w *Wallet) Deposit(n int) {
	w.rub += n
}

// Balance только читает — хватило бы и значения.
func (w Wallet) Balance() int {
	return w.rub
}

func main() {
	var w Wallet
	w.Deposit(100)
	w.Deposit(250)
	fmt.Println(w.Balance())   // 350
}
```

Обратите внимание: `var w Wallet` создаёт кошелёк с нулевым балансом (нулевое значение структуры — вы это знаете), и методы сразу готовы к работе — никакой отдельной «инициализации» не нужно. По совету консистентности `Balance` в боевом коде тоже сделали бы указательным, раз `Deposit` такой; здесь оставили значение, чтобы показать оба вида рядом.

## Методы можно вешать на любой именованный тип

Не только на структуры! Объявите именованный тип — и метод прикрепится хоть к числу:

```go
type Celsius float64

func (c Celsius) Describe() string {
	if c <= 0 {
		return "мороз"
	}
	return "тепло"
}

t := Celsius(-7)
fmt.Println(t.Describe())            // мороз
fmt.Println(Celsius(21).Describe())  // тепло
```

`Celsius` — это `float64` со своим именем, и теперь у температуры есть поведение. Единственное ограничение: тип должен быть объявлен в вашем же пакете — повесить метод прямо на встроенный `int` или `float64` нельзя, потому и заводят именованный тип-обёртку.

## Метод виден у переменной любого происхождения

Как бы вы ни создали значение — литералом, через `var`, через указатель — методы на месте:

```go
p := &Rect{W: 5, H: 2}  // p — указатель на Rect
fmt.Println(p.Area())   // 10 — метод со значением-получателем виден и через указатель
```

Здесь авторазыменование сработало в обратную сторону: `p.Area()` — это `(*p).Area()`. Итого симметрия: значение умеет вызывать указательные методы (Go возьмёт адрес), указатель — значенческие (Go разыменует). Думать об этом в повседневном коде почти не приходится — просто пишите точку.

## Типичные ошибки новичка

| Код | Что случится | Как чинить |
|---|---|---|
| `func (c Counter) Inc() { c.value++ }` | компилируется, но счётчик вечно 0 — росла копия | получатель-указатель: `func (c *Counter) Inc()` |
| `Area(r)` после объявления метода `(r Rect) Area()` | `undefined: Area` — метод не функция | вызывать через точку: `r.Area()` |
| `func (r *Rect) Scale(...)`, вызов `Rect{2, 3}.Scale(10)` | ошибка компиляции: у временного значения нет адреса | сначала в переменную: `r := Rect{2, 3}; r.Scale(10)` |
| `func (c *int) Double()` | ошибка: метод нельзя вешать на встроенный тип | именованный тип: `type MyInt int`, метод на нём |
| метод объявлен, но забыли получатель: `func Inc()` | это обычная функция, `c.Inc()` не найдёт её | вернуть скобки получателя на место |

## Запомнить

- Метод = функция с получателем (*receiver*): `func (r Rect) Area() int`; вызов — через точку: `r.Area()`.
- Получатель-значение (*value receiver*) — копия: читать можно, изменения пропадают.
- Получатель-указатель (*pointer receiver*) `func (c *Counter)` — метод меняет оригинал.
- `c.Inc()` на переменной работает сам: Go подставляет `(&c)`; временные значения адреса не имеют.
- Меняешь состояние или структура большая → указатель; только читаешь маленькую → значение.
- Хоть один метод указательный → делай указательными все методы типа.
- Методы вешаются на любой именованный тип своего пакета: `type Celsius float64` + `func (c Celsius) ...`.
