# Каналы — как горутины разговаривают

Прошлый уровень оставил вопрос открытым: горутины работают, а как передать результат? Писать в общую переменную опасно, слоты `res[i]` выручают лишь в простых случаях. Настоящий ответ Go — канал (*channel*): типизированная труба, по которой одна горутина отправляет значения, а другая принимает. Знаменитый девиз языка: «Не общайтесь через разделяемую память — разделяйте память через общение». Сегодня учимся общаться.

## Создание, отправка, приём

```go
ch := make(chan int) // канал целых чисел
```

Канал создаётся через `make` (как слайсы и карты) и указывает тип содержимого: `chan int`, `chan string`, `chan User`. Операции — стрелка `<-`, показывающая направление движения данных:

```go
ch <- 42        // отправка: значение УХОДИТ в канал
v := <-ch       // приём: значение ПРИХОДИТ из канала
```

Читается по стрелке: `ch <- 42` — «42 в канал», `<-ch` — «из канала».

## Первый осмысленный пример: результат из горутины

```go
func main() {
	ch := make(chan string)

	go func() {
		// ...долгая работа...
		ch <- "готово: 42" // отправляем результат
	}()

	msg := <-ch // ждём и получаем
	fmt.Println(msg) // готово: 42
}
```

Заметьте, что здесь нет ни `WaitGroup`, ни `Sleep` — и программа корректна. Почему? Из-за главного свойства каналов.

## Блокировка — это фича

Операции с каналом **блокируют**:

- отправка `ch <- v` ждёт, пока кто-нибудь не примет;
- приём `<-ch` ждёт, пока кто-нибудь не отправит.

Передача происходит только в момент встречи отправителя с получателем — это называют рандеву (*rendezvous*). Поэтому в примере выше `<-ch` в main честно ждёт горутину: канал — одновременно и почта, и синхронизация. Данные не теряются и не приходят «слишком рано».

Обратная сторона: если встреча невозможна, программа застревает навсегда. Go это замечает:

```go
func main() {
	ch := make(chan int)
	ch <- 1 // некому принимать: все горутины спят
	// fatal error: all goroutines are asleep - deadlock!
}
```

Взаимная блокировка (*deadlock*) — все горутины ждут друг друга, работать некому. Классические причины: отправка без получателя, приём из канала, в который никто не пишет, забытая горутина-отправитель.

## close: сигнал «больше не будет»

Отправитель может закрыть канал — объявить, что поток данных закончился:

```go
close(ch)
```

Приём из закрытого канала не блокирует: мгновенно возвращается **нулевое значение** типа. Отличить «настоящий ноль» от «канал закрыт» помогает знакомая ok-идиома:

```go
v, ok := <-ch
// ok == true  — настоящее значение из канала
// ok == false — канал закрыт и пуст, v — нулевое значение
```

Два железных правила:

- канал закрывает **отправитель** — тот, кто знает, что данных больше не будет;
- отправка в закрытый канал — **паника**. Повторное закрытие — тоже.

## range по каналу

Приёмник может перебирать канал циклом — как слайс, только вместо индексов «пока не закроют»:

```go
ch := make(chan int)

go func() {
	for i := 1; i <= 3; i++ {
		ch <- i * i
	}
	close(ch) // без close цикл range никогда не закончится!
}()

for v := range ch {
	fmt.Println(v)
}
// 1
// 4
// 9
```

`range` принимает значения по одному и завершается, когда канал закрыт и опустошён. Порядок гарантирован: канал — очередь, первым пришёл — первым ушёл (*FIFO*).

> [!WARNING]
> `range` по каналу без `close` со стороны отправителя — вечный сон: цикл будет ждать следующее значение, которое никогда не придёт. Если после такого зависания все горутины окажутся спящими, получите deadlock; если где-то ещё теплится жизнь — просто утечку застрявшей горутины. Отправили всё — закрывайте.

## Направленные каналы: самодокументация

В сигнатурах функций канал можно ограничить направлением:

```go
func produce(out chan<- int) { // только отправка: chan<- 
	out <- 1
}

func consume(in <-chan int) { // только приём: <-chan
	fmt.Println(<-in)
}
```

Стрелка в типе показывает, что функции разрешено: `chan<- int` — «канал, в который пишут», `<-chan int` — «канал, из которого читают». Попытка прочитать из `chan<-` — ошибка компиляции. Обычный `chan int` неявно приводится к любому из них, поэтому вызывающему коду ничего специально делать не надо. Это бесплатная страховка и документация: по сигнатуре видно, кто источник, а кто потребитель.

## Собираем паттерн: генератор

Функция, возвращающая канал, — идиома «генератор»:

```go
func countdown(from int) <-chan int {
	ch := make(chan int)
	go func() {
		for i := from; i >= 1; i-- {
			ch <- i
		}
		close(ch)
	}()
	return ch
}

for v := range countdown(3) {
	fmt.Println(v)
}
// 3
// 2
// 1
```

Внутри — своя горутина-отправитель, наружу — канал только для чтения. Вызывающий просто перебирает значения, не думая о горутинах вовсе. Из таких кирпичиков собираются конвейеры (*pipelines*) — цепочки стадий, где выход одной стадии становится входом следующей.

## Типичные ошибки новичка

| Код | Что случится | Как чинить |
|---|---|---|
| `ch := make(chan int); ch <- 1` в main без горутин | deadlock: некому принимать | приёмник в другой горутине (или буфер — следующий уровень) |
| `range ch`, а отправитель не закрыл канал | цикл ждёт вечно | `close(ch)` после последней отправки |
| `close(ch)` со стороны приёмника | отправители запаникуют при следующей отправке | закрывает только отправитель |
| отправка в закрытый канал | паника: `send on closed channel` | закрывать строго после ВСЕХ отправок |
| `var ch chan int` без make и работа с ним | nil-канал: блокировка навсегда | `ch := make(chan int)` |
| проверять «канал закрыт?» до чтения | такой операции нет | принимать с ok: `v, ok := <-ch` |

## Запомнить

- Канал — типизированная труба между горутинами: `ch := make(chan int)`; отправка `ch <- v`, приём `v := <-ch`.
- Обе операции блокируют до встречи отправителя с приёмником — канал передаёт данные И синхронизирует.
- Все горутины спят — deadlock: `fatal error: all goroutines are asleep`.
- `close(ch)` — сигнал «данных больше не будет»; закрывает только отправитель; отправка в закрытый — паника.
- Приём из закрытого: нулевое значение мгновенно; различать через `v, ok := <-ch`.
- `for v := range ch` перебирает до закрытия; порядок FIFO.
- Направления в сигнатурах: `chan<- int` — только отправка, `<-chan int` — только приём.
- Генератор: функция запускает горутину-отправителя и возвращает `<-chan T`.
