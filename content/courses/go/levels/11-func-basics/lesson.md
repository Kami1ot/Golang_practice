# Функции: основы — программа из кубиков

До сих пор весь ваш код жил в одном месте — внутри `main`. Для коротких программ это нормально, но стоит программе подрасти — и `main` превращается в простыню, в которой ничего не найти. Пора нарезать код на именованные кубики — функции (*functions*). Кстати, вы давно ими пользуетесь: `fmt.Println`, `strings.Contains`, `strconv.Atoi` — всё это функции, просто написали их не вы.

## Зачем нужны функции

Задача: поприветствовать трёх гостей. Без функций — копипаста:

```go
fmt.Println("Привет, Аня! Добро пожаловать в Go.")
fmt.Println("Привет, Боря! Добро пожаловать в Go.")
fmt.Println("Привет, Вера! Добро пожаловать в Go.")
```

Захотелось поменять текст — правим три места (и одно обязательно забудем). Функция объявляется один раз, а вызывается сколько угодно:

```go
package main

import "fmt"

func greet(name string) {
    fmt.Println("Привет, " + name + "! Добро пожаловать в Go.")
}

func main() {
    greet("Аня")
    greet("Боря")
    greet("Вера")
}
```

Вывод тот же, а текст приветствия теперь живёт в одном месте. У функций две работы:

- **убрать повторы** — одинаковый код пишется один раз;
- **разбить программу на смысловые куски** — `main` читается как оглавление, а детали спрятаны в функциях с говорящими именами.

## Синтаксис объявления

```go
func имя(параметры) типРезультата {
    тело
}
```

- `func` — ключевое слово: «дальше объявляется функция»;
- имя — по тем же правилам, что у переменных;
- параметры (*parameters*) — входные данные: имя и тип каждого;
- тип результата — что функция возвращает; не возвращает ничего — тип просто не пишется.

Простейшая функция-вычислитель:

```go
func square(x int) int {
    return x * x
}
```

Читается так: «функция `square` берёт `int` и возвращает `int`». Что именно вернуть, говорит `return`.

## Вызов и return

Объявление само по себе ничего не выполняет — код запускается вызовом (*call*): имя плюс аргументы в скобках.

```go
func square(x int) int {
    return x * x
}

func main() {
    a := square(4)          // x внутри функции получит 4
    fmt.Println(a)          // 16
    fmt.Println(square(10)) // 100 — результат можно сразу печатать
}
```

`return` делает две вещи сразу: **немедленно** завершает функцию и отдаёт значение наружу. Код после сработавшего `return` не выполняется — этим удобно пользоваться в ветках:

```go
func abs(x int) int {
    if x < 0 {
        return -x   // отрицательное: вернули и вышли
    }
    return x        // сюда попадаем только при x >= 0
}
```

> [!WARNING]
> Если у функции объявлен тип результата, `return` со значением обязан стоять на **каждом** пути выполнения. Уберите последний `return x` из `abs` — компилятор откажет: `missing return`.

## Параметры одного типа — короче

Два параметра `int` можно объявить полно — `(a int, b int)` — или сокращённо, указав тип один раз на всех:

```go
func add(a, b int) int {
    return a + b
}

func main() {
    fmt.Println(add(2, 3))   // 5
    fmt.Println(add(10, -4)) // 6
}
```

Аргументы (*arguments*) подставляются в параметры по порядку: в `add(2, 3)` двойка станет `a`, тройка — `b`. Типы обязаны совпадать: `add(2.5, 3)` не скомпилируется — `2.5` не `int`.

## Без параметров, без результата

Обе части необязательны. Все четыре формы:

| Форма | Объявление | Вызов |
|---|---|---|
| ничего не берёт, ничего не возвращает | `func line()` | `line()` |
| только берёт | `func greet(name string)` | `greet("Аня")` |
| только возвращает | `func luckyNumber() int` | `n := luckyNumber()` |
| берёт и возвращает | `func add(a, b int) int` | `s := add(2, 3)` |

```go
func line() {
    fmt.Println("----------")
}

func main() {
    line()
    fmt.Println("итого: 42")
    line()
}
// ----------
// итого: 42
// ----------
```

## Несколько возвращаемых значений

Фирменная черта Go: функция может вернуть **несколько** значений сразу. Типы результатов перечисляются в скобках через запятую, `return` отдаёт значения тоже через запятую:

```go
func divMod(a, b int) (int, int) {
    return a / b, a % b
}

func main() {
    d, m := divMod(17, 5)
    fmt.Println(d, m)   // 3 2
}
```

Одна функция — и частное, и остаток: не нужно считать дважды. Результаты принимают сразу в две переменные: `d, m := …` — по порядку, как они перечислены в `return`.

> [!NOTE]
> Пара `n, err := strconv.Atoi("42")` из прошлого уровня — та же механика! `Atoi` — обычная функция с двумя результатами: число и ошибка. Никакой магии — теперь вы умеете писать такие сами.

## Ненужное значение — в `_`

Go требует принять **все** результаты: `d := divMod(17, 5)` — ошибка `assignment mismatch`. А если нужен только остаток? Лишнее сбрасывают в пустой идентификатор (*blank identifier*) `_`:

```go
_, m := divMod(17, 5)
fmt.Println(m)   // 2
```

Вы уже делали так в `for _, v := range …`, когда индекс был не нужен, — это тот же `_`. В него можно выбросить любой из результатов, и на «не используется» он никогда не жалуется.

## Функции вызывают друг друга

Внутри функции можно звать любые другие — и стандартные, и свои:

```go
func area(w, h int) int {
    return w * h
}

func describe(w, h int) {
    fmt.Println("площадь:", area(w, h))
}

func main() {
    describe(3, 4)   // площадь: 12
}
```

`main` позвал `describe`, тот позвал `area` — обычное дело: программа и есть цепочка вызовов. Два факта напоследок:

- **`main` — тоже функция**, без параметров и результата. Просто вызываете её не вы, а Go — при старте программы.
- **Порядок объявления функций в файле не важен**: `main` может стоять первой, а помощники — ниже (или наоборот). Компилятор сначала читает весь файл целиком и только потом разбирается со связями.

## Аргументы передаются по значению

Функция получает **копию** аргумента (*pass by value*). Что бы она ни делала со своей копией числа или строки, оригинал снаружи не меняется:

```go
func tryChange(n int) {
    n = 100
    fmt.Println("внутри:", n)
}

func main() {
    n := 1
    tryChange(n)
    fmt.Println("снаружи:", n)
}
// внутри: 100
// снаружи: 1
```

Нужно изменённое значение — верните его через `return` и присвойте на месте вызова: `n = doubled(n)`.

> [!WARNING]
> «Функция не может испортить мои переменные» — приятное следствие копирования. Но иногда доступ к оригиналу правда нужен — для этого в Go есть указатели (*pointers*), они будут дальше в курсе. А со слайсами и картами история хитрее — к ней вернёмся там же.

> [!NOTE]
> Имя с заглавной буквы (`Area`) или со строчной (`area`) — в наших примерах разницы нет. Вообще же заглавная буква делает имя «публичным» для других пакетов — это станет важно позже. В задачах уровня пишите имена функций точно как в условии: проверка ищет именно их.

## Типичные ошибки новичка

| Код | Что случится | Как чинить |
|---|---|---|
| `func f(x int) { return x }` | `too many return values` — тип результата не объявлен | дописать тип: `func f(x int) int` |
| `return` забыт в одной из веток | `missing return` | вернуть значение на каждом пути |
| `d := divMod(17, 5)` | `assignment mismatch: 1 variable but divMod returns 2 values` | принять оба: `d, m := …` или `d, _ := …` |
| `q, r := divMod(17, 5)`, а `r` не используется | `declared and not used: r` | заменить ненужное на `_` |
| `add(2.5, 3)` при `func add(a, b int) int` | `cannot use 2.5 … as int value` | типы аргументов должны совпадать с параметрами |

## Запомнить

- `func имя(параметры) типРезультата { … }`; параметры одного типа — сокращённо: `a, b int`.
- Вызов — `имя(аргументы)`; аргументы подставляются в параметры по порядку.
- `return` немедленно завершает функцию; при объявленном результате обязан быть на всех путях.
- Несколько результатов: `(int, int)`; принять все — `d, m := …`; лишнее — в `_`.
- `n, err := strconv.Atoi(…)` — обычная функция с двумя результатами.
- `main` — тоже функция; порядок объявления функций в файле не важен.
- Аргументы передаются по значению: функция работает с копией, оригинал не меняется.
