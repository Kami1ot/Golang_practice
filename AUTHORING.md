# AUTHORING — как добавлять курсы и уровни

Два равноправных способа:
1. **Веб-админка** (#/admin, нужна роль admin) — формы с теми же проверками.
2. **Файлы в `content/courses/`** + `POST /api/reload` — валидатор перечислит
   проблемы с точными путями; пока есть ошибки, работает старый контент.

Reload требует админской сессии (cookie):

```powershell
# login.json: {"username":"...","password":"..."}
curl.exe -c cookies.txt -X POST http://127.0.0.1:8080/api/auth/login --data-binary "@login.json"
curl.exe -b cookies.txt -X POST http://127.0.0.1:8080/api/reload
```

Добавил курс/уровень — отметь чекбокс в ROADMAP.md.

## Анатомия курса

```
content/courses/<course-id>/
├── course.json                  # мета курса + явный список уровней
└── levels/<level-id>/
    ├── level.json               # мета уровня: requires, optional, xp
    ├── lesson.md                # урок (ОБЯЗАТЕЛЕН)
    ├── quiz.json                # тест по теории (опционален)
    ├── img/…                    # картинки урока (опционально)
    └── tasks/<task-id>/         # задачи по коду (опционально)
        ├── task.json
        ├── statement.md         # условие
        ├── starter.go           # заготовка в редакторе
        └── main_test.go         # ТОЛЬКО для type=unittest, скрытый
```

Язык: русский, ключевые термины дублируются на английском курсивом:
`переменная (*variable*)`. Общий тон — дружелюбный наставник, без канцелярита.

## course.json

```json
{
  "id": "go-basics",
  "title": "Основы Go",
  "description": "Одно-два предложения для карточки курса.",
  "levels": ["01-hello", "02-variables"]
}
```

- `id` == имя папки (проверяется).
- `levels` — все папки уровней; папка без записи в списке = ошибка загрузки.
  Порядок влияет только на разрешение ничьих при раскладке дерева.

## level.json

```json
{
  "id": "02-variables",
  "title": "Переменные и типы",
  "summary": "var, :=, базовые типы — одна строка под заголовком",
  "requires": ["01-hello"],
  "optional": false,
  "xp": 20,
  "group": "Основы"
}
```

- `requires: []` → корневой уровень; несколько id → уровень откроется после ВСЕХ.
- Циклы и ссылки на несуществующие уровни ловит валидатор.
- `optional: true` → бонусная ветка: рисуется пунктиром, не блокирует прогресс.
- `xp`: ориентир — 15 за вводный, 20–25 за обычный, 15 за бонус.
- `group` — секция на карте уровней («Основы», «Циклы и коллекции»…): карта рисует
  подпись-разделитель перед первым уровнем каждой новой группы. Уровни одной группы
  должны идти в course.json подряд. Внутри курса «Язык Go» новые темы = новые группы,
  отдельный курс — только для другой большой темы (другой язык и т.п.).

## Стандарт глубины уровня (после переработки 2026-07-14)

- **Урок**: 180–300 строк Markdown — зачем → синтаксис → 4–8 примеров с выводом →
  таблицы → типичные ошибки новичка → callouts → мини-итог «Запомнить».
- **Тест**: 6–7 вопросов, смесь всех четырёх типов, у каждого explanation.
- **Задачи**: 3 на уровень (у бонусных можно 2): разогрев → основная → со звёздочкой
  (required: false). У каждой 2–3 подсказки; io-задачи с 3–5 тест-кейсами
  (первый видимый, остальные hidden на крайние случаи).

## lesson.md

Обычный Markdown: заголовки, списки, таблицы, ```go-блоки (подсветка автоматическая).

Callouts в стиле GitHub:

```markdown
> [!NOTE]
> Полезное замечание.

> [!WARNING]
> Частая ошибка новичков.
```

Картинки: положить в папку уровня, сослаться относительным путём
`![схема](img/memory.png)`. Доступны только расширения картинок
(.png/.jpg/.jpeg/.gif/.svg/.webp) — quiz.json и main_test.go с фронта не скачать.

## quiz.json

```json
{
  "passScore": 1.0,
  "questions": [ … ]
}
```

`passScore` — доля правильных для зачёта (1.0 = все). 4 типа вопросов:

| type | поля ответа | как проверяется |
|---|---|---|
| `single` | `"answer": 1` — индекс в `options` | точное совпадение |
| `multi` | `"answers": [0, 2]` — индексы | точное множество, порядок не важен |
| `output` | `"answer": "7\n"` — строка | normalize: CRLF→LF, трим хвостовых пробелов/переводов |
| `blank` | `"answers": ["const"]` — любой подходит | трим пробелов; `"caseSensitive": false` для нечувствительности |

Общие поля вопроса: `id` (уникален в тесте), `type`, `prompt` (Markdown),
`explanation` (Markdown, показывается ПОСЛЕ проверки — и при верном, и при неверном ответе).
Для `output`: код инлайном в `"code"` или файлом `"codeFile": "q3.go"` (путь от папки уровня).
Для `single`/`multi`: `options` — массив Markdown-строк, минимум 2.

**Ответы никогда не уезжают клиенту** — сервер вырезает их из API сам,
об этом думать не нужно. Но и подсказок в `prompt` оставлять не стоит.

## Задача type="io" — программа целиком

```json
{
  "id": "sum-io",
  "type": "io",
  "title": "Сумма двух чисел",
  "required": true,
  "order": 1,
  "timeoutSec": 10,
  "tests": [
    { "name": "пример из условия", "stdin": "3 4\n", "stdout": "7\n", "hidden": false },
    { "name": "отрицательные",      "stdin": "-2 -3\n", "stdout": "-5\n", "hidden": true }
  ]
}
```

- Пользователь пишет весь `main.go`; программа получает `stdin`, сверяется `stdout`
  (через тот же normalize — хвостовой `\n` можно писать, можно нет).
- Первый тест-кейс = пример из условия, `hidden: false` (показывается в UI).
  Остальные — `hidden: true`: пользователь видит только вердикт, без данных.
- `required: false` → бонусная задача: не блокирует завершение уровня.
- `order` — порядок карточек на вкладке.

### Подсказки (обе разновидности задач)

```json
"hints": [
  "Мягкий намёк: куда смотреть в уроке.",
  "Конкретнее: какая конструкция нужна и как её собрать (но не готовый код)."
]
```

- Раскрываются по одной, от лёгкой к почти-решению; 2–3 штуки достаточно.
- Последняя подсказка может почти диктовать решение, но НЕ должна быть кодом,
  который можно сдать копипастой.
- Подсказки видны ученику по кнопке — не прячьте туда спойлеры к скрытым тестам.

## Задача type="unittest" — функции + скрытые тесты

```json
{ "id": "sum-func", "type": "unittest", "title": "Функция Sum",
  "required": true, "order": 2, "timeoutSec": 15 }
```

- `starter.go`: `package main` + заготовка функции с `// TODO` (func main НЕ нужен).
- `main_test.go`: `package main`, стандартный `testing`, имена `TestXxx`.
  Сообщения ошибок — на русском и информативные:
  `t.Errorf("Sum(3, 4) = %d, ожидалось 7", got)` — пользователь видит их в UI.
- Не полагаться на порядок выполнения тестов; один аспект — один Test*.
- В `statement.md` зафиксировать сигнатуру: «не меняйте имя и сигнатуру функции».

## Чеклист нового уровня

1. [ ] `level.json`: id == папка, requires указывают на существующие уровни
2. [ ] уровень добавлен в `levels` своего `course.json`
3. [ ] `lesson.md` покрывает ВСЁ, что нужно для решения задач уровня
       (ничего «из будущих уровней» в задачах)
4. [ ] в тесте 3–4 вопроса, у каждого — `explanation`
5. [ ] у io-задач: первый тест видимый, 2–3 скрытых на краевые случаи
       (ноль, отрицательные, большие значения)
6. [ ] задачи решаемы кодом из урока; сам(а) реши каждую задачу через UI
7. [ ] `POST /api/reload` → `{"ok":true}`
8. [ ] пройди уровень в браузере от начала до конца

## Частые ошибки авторинга

- JSON не поддерживает комментарии и лишние запятые; неизвестные поля = ошибка
  (защита от опечаток). Загрузчик печатает файл и строку:колонку.
- В `stdout` тест-кейсов писать `\n` в конце — как реально печатает `fmt.Println`.
- Кириллица в задачах — ок (UTF-8 везде), но имена файлов и id — латиницей,
  kebab-case: `02-variables`, `sum-func`.
