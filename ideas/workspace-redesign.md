# Идея: редизайн страницы уровня — двухпанельный workspace (стиль Практикума)

Статус: **РЕАЛИЗОВАНО 2026-07-17** (в тот же день, что и записано).
Реализация: web/js/views/workspace.js (+ level.js как диспетчер режимов),
бэкенд заметок в store/httpapi (notes.go), стили — блок «Workspace» в app.css,
макет — «Экран 4» в design/mockup.html. Отличия от спеки ниже помечены курсивом:
*грид называется .ws-grid (класс .workspace занят режимом #app); пункт сайдбара —
«Теория»; переключение режимов — по window resize (событие matchMedia не срабатывает
в эмуляции вьюпорта); клэмп сплиттера 24–72% + минимум правой панели 360px.*
Документ сохранён как история решения.

## Цель

Страница прохождения уровня занимает весь экран и разделена вертикально на две
панели с изменяемой шириной: слева — учебный контент (теория, тест, задачи)
с сайдбаром разделов, справа — рабочая зона с переключателем (IDE / Заметки).

## Текущее состояние (что меняется)

- `web/js/views/level.js` — страница уровня: три таба (урок/тест/задачи)
  в один скролл; задачи (`web/js/views/tasks.js`) — вертикальная стопка карточек;
  «сплит» внутри карточки — CSS-only (грид под `#app.wide` при ≥1100px),
  без ручки перетаскивания и без переключателя задач.
- **Черновики уже на сервере**: per-task, `PUT …/tasks/{t}/draft`, автосейв
  с дебаунсом 1 с, колонка `progress.draft`. Это идеально ложится на
  «один редактор, при переключении задачи меняется только контент» —
  переиспользуется как есть.
- Drawer чат-наставника (`web/js/views/chat.js`) — готовый прецедент
  правой панели; сосуществует с новым layout (FAB поверх).
- `--topbar-h` уже вычисляется через ResizeObserver — высота workspace
  считается от неё.

## Целевой layout

```
┌ topbar ──────────────────────────────────────────────────┐
├──────────────────────────────╥───────────────────────────┤
│ ЛЕВАЯ ПАНЕЛЬ                 ║ ПРАВАЯ ПАНЕЛЬ             │
│ ┌────────┬─────────────────┐ ║ ┌──────────────────┬────┐ │
│ │сайдбар │ контент:        │ ║ │ редактор кода    │IDE │ │
│ │Теория  │ урок / тест /   │ ║ │ + результаты     │Зам.│ │
│ │Тест    │ условие задачи  │ ║ │ или заметки      │    │ │
│ │Задачи: │                 │ ║ │                  │    │ │
│ │ 1. ✓   │                 │ ║ │                  │    │ │
│ │ 2. …   │                 │ ║ │                  │    │ │
│ └────────┴─────────────────┘ ║ └──────────────────┴────┘ │
└──────────────────────────────╨───────────────────────────┘
                    ║ — draggable-сплиттер
```

- Высота: `calc(100vh - var(--topbar-h))`, панели скроллятся независимо.
- Сплиттер: vanilla JS (drag меняет CSS-переменную ширины), позиция
  запоминается в localStorage (это UI-предпочтение, сервер не нужен).
- Токены дизайна — те же (`web/css/app.css`), тёмная IDE-стилистика.

## Левая панель

- Сайдбар разделов: **Теория / Тест / Задачи** (задачи — списком, каждая
  отдельным пунктом с отметкой статуса — как сейчас галочки/счётчики на табах).
- Контент: теория — `renderMD(lessonMd)`; тест — текущий `renderQuiz`;
  задача — условие + примеры + прогрессивные подсказки (текущее содержимое
  `.task-side`), **по одной задаче на экран** вместо стопки карточек.

## Правая панель

- Узкий переключатель зон в стиле activity bar VS Code: **IDE** и **Заметки** —
  **по правому краю панели** (у края экрана): так он зеркален левому сайдбару,
  не сливается с ним визуально и не стоит между условием задачи и редактором.
- **IDE**: один экземпляр CodeMirror; при переключении задач меняется только
  контент (шаблон/черновик задачи), окно то же. Кнопки Запустить / Сбросить /
  🎓 Наставник, снизу — результаты прогона (текущий `renderResults`:
  compile error, per-test строки, diff expected/actual). Автосейв черновика —
  существующий `api.saveDraft`.
- **Заметки**: Markdown, **одна заметка на уровень**; textarea + предпросмотр
  через существующий `renderMD`; автосейв с дебаунсом по образцу черновиков.

## Связка панелей (поведение)

- Выбрал задачу слева → справа автоматически открывается IDE с шаблоном/черновиком
  этой задачи.
- Выбрал IDE справа, когда слева не задачи → слева переброс на задачи
  (первая незавершённая или последняя открытая).
- Заметки доступны всегда — при чтении теории и прохождении теста тоже.

## Заметки — бэкенд (новая фича)

- `internal/store/schema.sql`: таблица `notes(user_id, course_id, level_id,
  body text, updated_at timestamptz, PRIMARY KEY(user_id, course_id, level_id))` —
  только сырые факты per-user, по инварианту 3.
- API: `GET`/`PUT /api/courses/{course}/levels/{level}/note` (requireUser).
- Кабинет: секция «Заметки» в `web/js/views/profile.js` — список заметок
  с именем **{курс}-{модуль}-{уровень}**, где «модуль» — существующее поле
  `group` уровня («Основы», «Циклы и коллекции», …); каждая заметка —
  ссылка на свой уровень. Данные: расширить `GET /api/profile` или отдельный
  `GET /api/notes`.

## Fallback и инварианты

- Ниже ~1100px — откат к текущему табовому виду (существующий код level.js
  сохраняется как fallback-режим).
- `design/mockup.html` обновить **синхронно** с app.css (инвариант раздела
  «Дизайн» в CLAUDE.md) — добавить в мокап workspace-экран.
- Инвариант 1 не трогается: ответы теста и скрытые тесты по-прежнему
  не уезжают на клиент; API уровня не меняется (добавляется только note).
- CodeMirror при показе из скрытого состояния требует `.refresh()` —
  учесть при переключении зон (грабля уже известна по табам).

## Этапы реализации (когда возьмёмся)

1. Каркас workspace: две панели + сплиттер + левый сайдбар; контент рендерят
   существующие renderMD/renderQuiz; правая панель — пустая заглушка.
2. IDE-зона: один редактор, переключение задач, результаты, автосейв черновиков.
3. Заметки: schema + store + httpapi + зона справа + секция в кабинете.
4. Fallback для узких экранов, обновление design/mockup.html, полировка.
